# 存储、导入与导出规格

覆盖已保存的会话、分组、凭据、Sender 命令、命令历史、设置的存储规则，以及 `.kanso` 数据文件的导入导出和 OpenSSH 配置导入。存储的技术方案（SQLite、表结构、迁移）见 `architecture.md` 存储一节；本文只规定行为。

## 1. 数据实体

| 实体 | 内容 | 敏感程度 |
|---|---|---|
| 会话配置 | 字段见 `ui-shell.md` §5；**不包含任何密码或口令** | 普通 |
| 分组 | id、名称；只有一层，不支持嵌套 | 普通 |
| 凭据 | 密码、私钥口令；按会话 id 关联 | **机密** |
| Sender 命令 | 名称、文本、行尾（无 / LF / CRLF）、作用域 | 普通 |
| 命令历史 | 补全用，记录执行过的命令 | **可能含敏感内容** |
| 设置 | 外观、字体、面板、快捷键、行为开关等 | 普通 |
| 窗口状态 | 大小、是否最大化、面板布局 | 普通 |

## 2. 凭据

- 凭据**和会话配置分开存放**。会话配置可以随意交给界面显示，凭据只在打开会话的那一刻读取。
- **新版存进系统的凭据库**：macOS 是 Keychain，Windows 是 Credential Manager，Linux 是 Secret Service。数据库里只保存一个引用。
  - 旧版没有用 Keychain，而是用一个和本机绑定的密钥加密后存成文件，原因是**未签名的开发版每次构建后签名身份都会变，Keychain 会反复弹出授权提示**。新版的正式构建和开发构建都要使用**固定的签名身份和 Keychain 访问组**，避免出现这个问题。开发期间如果仍然频繁弹窗，可以提供一个仅限开发构建使用的加密文件后端。
  - Linux 上 Secret Service 不可用时（例如没有桌面环境），退回到加密文件：用本机 machine-id 和账户名派生密钥，加上文件里保存的随机盐，用 AEAD 加密。这种方式只保护静态存储的文件，无法防范同一账户下运行的其他程序。
- 凭据读取失败（例如数据来自别的机器）时，**当作没有保存过凭据**，继续运行，下次连接时再向用户询问。
- 删除会话时，同时删除它的凭据。
- 导出时**绝不包含凭据**；导入文件里如果出现凭据字段，一律忽略。

## 3. 会话与分组的一致性规则

- 删除会话时，一起删除：它的凭据，以及**作用域只针对这个会话**的 Sender 命令。
- **删除分组**时，组里的会话（连同凭据）以及作用域是这个分组或组内会话的 Sender 命令都会被删除。删除前要确认，并告诉用户会删掉多少个会话和命令。
- 会话引用的分组不存在了，就把它放回顶层，不能让会话"消失"。
- 跳板机引用失效时的处理，见 `ssh.md` §5。
- **跳板链出错（循环、引用的会话不存在、类型不对）时，必须报错，不能悄悄改成直连**：同名主机在另一个网络里可能是另一台机器。

## 4. Sender 命令

- 作用域有四种：某个会话 / 某个分组 / 某种会话类型（SSH 或本地 shell）/ 全局。
- 作用域指向的会话或分组不存在时，退回到全局，因为全局这一级总是存在的。
- 最多保存 **1000** 条。

## 5. 命令历史

- 最多 **5000** 条；每条最长 **500** 个字符，超过的不记录（多半是误捕获的输出）。
- 满了以后淘汰**最久没用过的**，而不是最早记录的，常用命令不能只因为记得早就被挤掉。
- 写入频繁（每执行一条命令写一次），所以写入要尽量小，不要每次重写全部历史。
- 历史可能包含敏感内容：文件只允许当前用户读取。"编辑 → 清除命令历史"可以全部清空。
- 以空格开头的命令不记录（见 `terminal.md` §5.2）。

## 6. `.kanso` 数据文件（导出与导入）

### 6.1 导出（会话 → 导出数据…）
- 内容：已保存的会话（不含凭据）、分组、Sender 命令、设置。
- 格式：JSON，扩展名 `.kanso`。文件里带应用标记和格式版本号，便于识别。
- 导出时自动加上扩展名。

### 6.2 导入（会话 → 导入数据…）
- **只接受 `.kanso` 扩展名**（不区分大小写），并且要检查文件里的应用标记：不是 Kanso 的数据文件，或者版本比当前程序认识的新，都要拒绝，并说明原因。
- **合并规则**：
  - 按 id 匹配，id 相同就用文件里的替换本地的；
  - 其他的都作为新数据加入；
  - **不删除本地任何数据**。
  - 被替换的会话保留本地已经保存的凭据。
- 导入后修正不一致的引用：会话引用的分组不存在时放回顶层；跳板引用失效时清除；Sender 命令作用域失效时退回全局。
- **单条数据有问题时，只跳过这一条**，不能让整个文件导入失败。旧版就出过这样的问题：只因为文件里有一条已经不支持的会话类型，就提示"不是 Kanso 数据文件"，导致整个文件都导不进来。
- 导入结束后报告：新增了多少、更新了多少、跳过了多少，以及跳过的原因。

### 6.3 兼容旧 GPL 版的导出文件（推荐支持）
- 旧版导出的 `.kanso` 文件（应用标记为 "Kanso"，格式版本 1–3）可以导入。这属于数据格式兼容，不涉及任何代码。
- 旧版的差异：
  - 版本 1 的 Sender 命令没有作用域，按全局处理；
  - 版本 3 之前的命令带有 `format` 字段，忽略它，按文本发送；
  - 已经不支持的会话类型（ftp、serial）跳过，并在报告里说明。
- 旧版的凭据文件**不迁移**，因为它与机器绑定，而且导出文件里本来就没有凭据。导入后第一次连接时再向用户询问密码。

## 7. OpenSSH 配置导入

入口：会话 → 导入 OpenSSH 配置…（也在会话启动器"已保存的会话"标题旁的菜单里）。默认读取 `~/.ssh/config`，也可以选择其他文件。

### 7.1 解析（按 `ssh_config(5)` 的语义）
- **每个只匹配一台主机的 `Host` 模式就是一个别名**；含 `*`、`?` 或者以 `!` 开头的模式都不算。同一个别名出现多次只算一个，它的多个配置块会合并起来。
- 对每个别名，按 `ssh 别名` 的方式求值：
  - 按文件顺序扫描所有能选中这个别名的配置块，**每个选项取第一次出现的值**。所以放在前面的 `Host *` 相当于给后面的所有主机设了默认值。
  - 模式匹配：`*` 匹配任意长度，`?` 匹配一个字符，不区分大小写；带 `!` 的否定模式一旦匹配，就否决整个配置块。
- 支持的选项：`HostName`、`Port`、`User`、`IdentityFile`、`ProxyJump`、`Include`。
  - `Include`：路径支持 `~` 展开，相对路径以 `~/.ssh` 为基准，文件名可以带通配符（例如 `config.d/*`）。被引入的内容在 `Include` 所在位置展开：被引入文件开头（第一个 Host 之前）的行属于引入处所在的块；被引入文件里的 Host 行只在该文件内部开始新块，**回到外层文件后恢复外层原来的块**，`Include` 之后的行仍属于外层那个块（用 OpenSSH 10.5 的 `ssh -G` 实测确认）。处于未选中块里的 `Include` 不会被读取。最多嵌套 **16** 层，与 OpenSSH 一致。读不到的文件直接跳过，与 ssh 的行为一致。
  - `%` 替换：`%d`（主目录）、`%u`（本地用户名）等，按 OpenSSH 的规则替换。
- 语法：`关键字 值` 和 `关键字=值` 两种写法都支持，关键字不区分大小写；双引号可以把带空格的内容括成一个词。以 `#` 开头的行是注释；行内**以 `#` 开头的词**开始行内注释（`User bob # x` 的值是 `bob`），词中间的 `#` 属于值（`User u#1` 的值是 `u#1`）。这是 `ssh -G` 实测的行为。
- 默认值：
  - 没写 `HostName`：用别名本身；
  - 没写 `Port`：22；
  - 没写 `User`：本地用户名，因为 ssh 这时就是用本地用户登录；
  - 没写 `IdentityFile`：按 id_ed25519、id_ecdsa、id_rsa 的顺序找 `~/.ssh` 下**实际存在的第一个**，认证方式设为私钥；一个都没有时，设为密码。

### 7.2 导入对话框
- 列出每个别名以及它解析后的连接目标（`用户@主机:端口`、私钥、跳板机）。
- 用户勾选要导入哪些，并选择放到哪个分组。
- **已经保存过的主机**要标出来。判断标准：已有会话的名称与别名相同，或者主机、端口、用户名三者完全相同。导入时**原地更新**这个会话，不新增重复项。

### 7.3 导入规则
- **更新已有会话时**：配置文件里没提到的东西（名称、颜色、分组、编码、手动设置的跳板机）都保留。只有文件里明确写了私钥时，才修改认证方式。如果把一个密码认证的会话改成默认私钥，会把它保存的密码一起丢掉，所以不能这样做。
- **ProxyJump**：
  - **只有一跳的**才导入为跳板机。跳板机可以是同一个文件里的别名，也可以是 `[用户@]主机[:端口]` 这种写法（IPv6 写成 `[地址]:端口`）。后一种情况下，先找有没有连接目标相同的已保存会话，没有就新建一个，名称用主机名。
  - 勾选了某个主机时，它引用的跳板机也会被一起导入，即使用户没有勾选那个跳板机。
  - **多跳的不导入**，会话本身照常保存，只是没有跳板机，并在报告里给出警告。原因是每个会话只能指定一个跳板机，而且不能因为某一台主机的跳板链去改动其他会话共用的跳板机。
  - 已经有跳板机的会话，不会被导入覆盖。
- 密码不在配置文件里，导入的会话第一次连接时会询问密码。
- 导入结束后报告：新增多少、更新多少、额外导入了多少跳板机、忽略了多少个多跳 ProxyJump，以及每条警告。

### 7.4 [MAS] 商店版
需要用户授权 `~/.ssh` 目录或配置文件（见 `design.md` §5）。

## 8. 存储位置

- Direct 版：
  - macOS 放在 `~/Library/Application Support/<bundle id>/`；
  - Windows 放在 `%APPDATA%`；
  - Linux 放在 `$XDG_CONFIG_HOME`。
- **Windows 便携模式**：可执行文件旁边有 `data` 目录时，所有数据都存到这个目录里，整个应用可以作为一个文件夹随意移动（VS Code 的做法）。便携版的压缩包自带这个目录，安装版不会创建它。
- 本地 shell 的 zsh shim 也放在应用数据目录下（见 `local-shell.md` §5）。
- 包含敏感内容的文件（命令历史、加密凭据的后备文件）只允许当前用户读写。

## 9. 设置

- 所有设置都有默认值。"帮助 → 恢复默认设置…"会把设置和快捷键全部恢复默认，但**不动**会话、分组、Sender 命令和历史。
- 设置的数据结构要带版本号；遇到不认识的字段时忽略，不能因此报错，保证新旧版本之间能互相读取。

## 10. 验收用例

- 删除一个会话后，它的凭据和只属于它的 Sender 命令都消失；全局命令不受影响。
- 删除分组前，确认框里显示会删除多少个会话和命令。
- 导出文件里没有任何密码或口令。
- 导入一个包含已不支持会话类型的旧导出文件：其余数据全部导入成功，报告中说明跳过了哪些。
- 版本号比当前程序新的文件会被拒绝，并说明原因。
- 用含 `Host *`、`Include config.d/*`、否定模式和多跳 ProxyJump 的配置文件测试，解析结果与 `ssh -G 别名` 的输出一致（只比较本文支持的那几个选项）。
- 导入时不会覆盖已保存会话的名称、颜色、分组，也不会覆盖手动设置的跳板机。
- 命令历史满了以后，常用的旧命令依然保留。

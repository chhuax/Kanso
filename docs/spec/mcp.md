# MCP 服务规格

覆盖 Kanso 作为 MCP（Model Context Protocol）服务端，把已保存的会话、终端标签和 SFTP 能力提供给外部 AI 工具（Claude Code、Codex 等）调用：启用与接入、授权模型、工具清单、与用户操作的协同、输出处理、活动记录、界面和错误约定。进程结构与模块落点见 `architecture.md` §16。

协议依据：MCP 规范（modelcontextprotocol.io，以协议版本协商结果为准）、JSON-RPC 2.0。Kanso 不内置 AI，**不做 MCP 客户端**。

### 已定决策（2026-11-17）

- 角色：只做 MCP 服务端，供本机的 AI 工具连接。
- 渠道：第一版只做 Direct。MAS 和 Setapp 见 §11。
- 授权粒度：按已保存的会话授权；已授权到"完全"级别的会话，执行命令和写文件**不逐次弹确认**。
- 凭据永远不经 MCP 暴露：任何工具都不返回密码、口令、私钥内容或其引用。

- D1 App 未运行：AI 工具连接时 Kanso 没在运行，**不自动拉起**，返回明确错误。自动拉起会让用户在不知情时打开一个带着授权的 App。
- D2 执行前确认：不提供"已授权为完全仍需逐次确认"的开关。
- D3 临时会话：未保存的临时连接、未保存的本地标签**不能授权**，MCP 看不到它们。
- D4 日志保留：审计日志保留 30 天且最多 10000 条，先到者为准。
- 需要用户参与认证的主机（MFA 等）：MCP **从不弹出认证提问**，这类主机的前提是用户先在 Kanso 里把它连上，见 §2.4。
- 客户端令牌：连接 MCP 必须带 Kanso 生成的令牌，可以随时重新生成使旧令牌作废，见 §1.1。
- 借用与自建连接：MCP 借用的、由用户建立的连接，在用户关闭最后一个标签时立即释放；MCP 自己建立的连接按 5 分钟空闲释放。见 §2.4。
- 只读级别不新建连接，只复用已有连接，见 §2.1。
- 客户端所在标签：同时按控制终端和进程祖先链识别，见 §2.5。

## 1. 启用与接入

- **全局开关**：设置 → MCP，默认关闭。关闭时不接受任何连接；从开到关时，立即断开所有已连接的客户端，正在执行的调用按 §4.4 中断。
- **接入方式**：AI 工具以 stdio 方式启动随 App 附带的 `kanso-mcp` 程序，由它把请求转交给正在运行的 Kanso。用户在 AI 工具里配置的就是这个程序的绝对路径，不带参数。
  - 设置页显示该路径，选择 Claude Code 或 Codex 后显示对应的接入命令。Windows 命令在 PowerShell 里执行。
  - App 被移动位置后路径会变，设置页显示的总是当前路径。
- **第一版不提供 HTTP 传输**。本机 HTTP 端口要额外处理 token、`Origin` 校验和 DNS rebinding，而 stdio 加上仅限当前用户访问的本机通道已经能满足本机 AI 工具的需求。
- **Kanso 未运行或开关关闭**：`kanso-mcp` 对客户端的初始化请求回一个 JSON-RPC 错误，然后退出，不自动拉起 App。两种情况必须能区分，分别说明"Kanso is not running"或"MCP is disabled in Kanso settings"，让用户知道该做什么。
- **多个客户端**：允许多个 AI 工具同时连接，每个连接是一个独立的 MCP 会话，有各自的编号和客户端名称（取自初始化请求里的 `clientInfo`；没有时显示"未知客户端"）。客户端名称由对方自报，**不能作为授权依据**，只用于显示和日志。
- 同时连接的客户端最多 16 个，超出时拒绝新连接并说明原因。
- 退出 Kanso 时断开所有客户端，正在执行的调用按 §4.4 中断。

### 1.1 客户端令牌

本机通道只校验对端是不是当前用户（§8），同一用户下的任何程序都能连上。如果没有令牌，任何本机程序都能借用户已经完成 MFA 的连接拿到远端 shell。令牌把能连接的程序限定为"用户亲手配置过的 AI 工具"。

- 第一次打开总开关时，Kanso 生成一个随机令牌（至少 128 位熵）。令牌保存在 macOS 钥匙串或 Windows 凭据管理器中。数据库和 `.kanso` 导出文件不含令牌。
- 设置页显示并复制 Claude Code、Codex 的完整接入命令，令牌以环境变量 `KANSO_MCP_TOKEN` 的形式写进 `kanso-mcp` 的启动配置，无需单独复制或填写令牌。
- 令牌缺失或不匹配时，拒绝连接，对初始化请求回"Invalid or missing Kanso MCP token"，并在活动记录（§6）里记一条。
- 设置页提供"重新生成令牌"：旧令牌立即作废，用旧令牌建立的连接立即断开。用户要把新配置重新粘贴到各个 AI 工具里。
- 令牌会以明文出现在 AI 工具的配置文件里，所以它只能防住"没有被用户配置过的程序"，防不住能读这些配置文件的程序。设置页的令牌旁边用一句话说明这一点。

## 2. 授权模型

### 2.1 访问级别

每个**已保存的会话**有一个 MCP 访问级别，默认**关闭**：

| 级别 | 允许的操作 |
|---|---|
| 关闭 | MCP 看不到这个会话及其标签，引用它的调用一律按"不存在"处理 |
| 只读 | 列出会话与标签；读取终端屏幕和回滚；查询工作目录；SFTP 列目录、查看属性、读文件。**只复用已有连接，不新建连接**（§2.4） |
| 完全 | 只读的全部操作，加上：打开新标签；在终端里执行命令、输入文字和按键；在 SSH 会话上后台执行命令；SFTP 写文件、新建目录、删除、重命名、上传、下载；关闭由 MCP 自己打开的标签 |

- 已打开的标签继承它所属会话的级别。同一个会话开了多个标签时，级别对所有标签生效。
- **"关闭"级别要让会话完全不可见**，而不是只返回"无权限"：会话名称和主机地址本身就可能是敏感信息。
- **"只读"也能看到敏感内容**：终端屏幕上可能有密钥、令牌、数据库查询结果。把级别从关闭改为只读或完全时要说明这一点：会话编辑对话框在字段下方显示一句提示，不弹框；会话启动器的"…"菜单没有放提示的地方，改为弹出一次确认，用户确认后才生效（§7.2）。
- **级别变更立即生效**，包括对正在执行的调用：降级后，正在等待结果的调用按 §4.4 中断，后续调用按新级别判断。已经发到远端的命令无法撤回，中断只是停止等待。
- 总开关关闭等同于所有会话都是"关闭"，但不改动各会话已设的级别。

### 2.2 授权的存储与传播

- 访问级别**只存在本机**，不进入 `.kanso` 导出文件，也不参与将来的同步。导入的会话一律从"关闭"开始，避免导入一个文件就悄悄给 AI 开了权限。
- 删除会话时，同时删除它的授权和相关的临时状态（活动记录保留，见 §6）。
- 复制会话（另存为）时，新会话的级别为"关闭"。

### 2.3 跳板机

- 被授权的会话通过跳板机连接时，跳板机只作为传输通道，**不需要单独授权**，MCP 也不能对跳板机本身执行任何操作。
- 跳板机作为独立会话时有它自己的级别，与它是否被别人用作跳板无关。

### 2.4 凭据与需要用户参与的认证

- 工具返回的会话信息里没有任何凭据字段，也不说明凭据是否已保存。
- **只读级别不新建连接**：访问级别为只读的会话，所有调用（SFTP 列目录和读文件、查询工作目录等）都只能使用已有连接，没有连接时返回 `NOT_CONNECTED`，不去登录服务器。判断依据是会话的级别，而不是工具本身是不是只读。这样，只读授权不会在服务器上留下 AI 发起的登录记录，也不会在没有终端标签的情况下去服务器上执行查询脚本。
- **完全级别可以新建连接，但一律不向用户提问**。访问级别为完全的会话，任何工具在没有现成连接时都会新建连接，认证过程中只要需要人参与，就立即放弃这次连接并返回 `NEEDS_USER`，不弹对话框，也不等待。需要人参与的情况包括：
  - keyboard-interactive（验证码、MFA，以及只问密码的 keyboard-interactive）；
  - 没有保存密码、需要当场输入；
  - 私钥有口令且没有保存；
  - 首次见到的主机密钥，或者主机密钥已变更。
- 不需要人参与的认证照常自动完成：已保存的密码、没有口令或口令已保存的私钥、ssh-agent，以及已在 known_hosts 里且匹配的主机密钥。
- **复用已有连接**：会话已经有已认证的连接时，MCP 直接复用，不重新认证。需要 MFA 的主机就靠这一点工作：用户先在 Kanso 里打开这个会话、完成一次验证，之后 AI 的调用都走这条连接。
  - "会话的连接"指从这个已保存会话打开的标签（包括复制出来的标签）所用的连接，以及 MCP 为它新建的连接。
  - 用户把同一个会话分别打开了两次，就有两条独立连接，这时取最近建立、而且仍然存活的那条。
- **连接的释放**分两种：
  - **借用**：用户建立的连接被 MCP 使用。用户关闭这条连接上的最后一个标签时，MCP 的引用立即释放，连接随即断开，与没有 MCP 时一样（`ssh.md` §6）。用户关掉标签，就意味着 AI 也不能再用这条连接。
  - **自建**：MCP 新建的连接，在 MCP 最后一次使用 5 分钟后释放。期间用户打开了这个会话的标签，连接就与用户共享，按 `ssh.md` §6 的引用计数断开。
- `NEEDS_USER` 和 `NOT_CONNECTED` 的说明里写明具体原因和处理办法（"ask the user to open this session in Kanso first"），让 AI 能转告用户。
- 如果建立连接的过程恰好与用户在 Kanso 里打开同一会话同时发生，两者各走各的：用户那边照常提问，MCP 这边照常失败，不会把用户的提问算作 MCP 的。

### 2.5 客户端自己所在的标签

在 Kanso 本地标签里运行的 AI CLI 连接 MCP 时，它所在的标签就是它自己的终端。对这个标签做写操作（执行命令、输入文字或按键）会打乱 AI 自身的界面，而且容易形成自我回馈的循环。

- App 用两条线索找出客户端所在的标签，命中任一条，就在这个 MCP 会话里把该标签标记为"客户端所在标签"：
  - **控制终端**：`kanso-mcp` 连接时上报自己控制终端的设备号（以及设备名），App 取本地标签终端设备的设备号与之比对；旧版转发程序没有设备号时退回比较设备路径。不能直接比较路径：转发程序拿到的是 `/dev/tty` 这个别名，与标签的 `/dev/ttysNNN` 不会相同。
  - **进程祖先链**：App 取得 `kanso-mcp` 的进程号，沿父进程往上找，看它是否从某个本地标签的 shell 启动。这样，AI 工具用脱离终端的方式启动 MCP 服务时也能识别。祖先链在每次判定时重新计算，不在连接时缓存，避免进程号复用后沿用过期结果；对端进程已退出时不命中。
- 对该标签的**写操作一律拒绝**，读操作照常允许。
- 两条线索都没有命中时不做标记，按普通规则处理，例如 AI 工具在 Kanso 外运行。
- **已知盲区**：用户在本地标签里先进入 tmux 或 screen，再在其中运行 AI 工具时，两条线索都指向 tmux 或 screen，而不是 Kanso 的标签，识别不出来。在设置页总开关的悬停提示里写明这一点（§7.1）。

## 3. 工具

工具名统一加 `kanso_` 前缀，避免和客户端里其他 MCP 服务的工具重名。每个工具按 MCP 规范标注 `readOnlyHint`、`destructiveHint`，并提供参数的 JSON Schema；下文"级别"列为调用所需的最低访问级别。

会话用会话 id 引用，标签用标签 id 引用。标签 id 在本次 App 运行期间保持不变，标签关闭后作废，不会复用。

### 3.1 会话与标签

| 工具 | 级别 | 行为 |
|---|---|---|
| `kanso_list_sessions` | 只读 | 列出级别不是"关闭"的已保存会话：id、名称、类型（本地 / SSH / SFTP）、主机、端口、用户名、分组名、访问级别，以及它的已打开标签。每个标签包含：标签 id、标题、连接状态（连接中 / 已连接 / 已关闭）、活动状态（空闲 / 命令运行中 / AI CLI 运行中）、是否锁定、是否正在 ZMODEM/XMODEM 传输、是否为 MCP 打开、是否为客户端所在标签。可按名称或分组过滤 |
| `kanso_get_cwd` | 只读 | 查询标签当前的工作目录。规则与用户按 ⌘J 时相同：有 OSC 7 用 OSC 7；SSH 会话没有时按 `ssh.md` §10 到服务器上查；本地会话按 `local-shell.md` 的规则查前台进程。失败时返回该规格定义的具体原因 |

### 3.2 读取终端

| 工具 | 级别 | 行为 |
|---|---|---|
| `kanso_terminal_read` | 只读 | 返回标签的可见屏幕文本，或回滚里最近 N 行（默认 200，最多 2000）。附带光标位置、屏幕尺寸，以及是否处于备用屏幕（全屏 TUI）。输出处理见 §5 |

### 3.3 终端操作

| 工具 | 级别 | 行为 |
|---|---|---|
| `kanso_open_tab` | 完全 | 用已保存的会话打开一个新标签，等连接建立（或失败）后返回标签 id。标签放进最前面窗口的当前分屏；没有窗口时新建一个窗口。**不切换用户当前的标签，不抢键盘焦点**。会话已有已认证的连接时直接复用（相当于复制标签），不再认证；没有时按 §2.4 新建连接，需要人参与认证就返回 `NEEDS_USER` |
| `kanso_close_tab` | 完全 | 只能关闭**本 MCP 会话打开的**标签。其他标签（包括用户自己开的）一律拒绝。客户端断开后，它打开的标签保留下来，变成普通标签：去掉"由 MCP 打开"标记，任何客户端都不能再关闭它 |
| `kanso_terminal_run` | 完全 | 在标签里输入一条命令并回车，等它返回提示符，再返回这条命令的输出。命令文本只能是一行可打印文字，不能含控制字符（需要按键请用 `kanso_terminal_send`），否则返回 `INVALID_ARGUMENT`。前置条件、完成判断和超时见 §4.2 |
| `kanso_terminal_send` | 完全 | 向标签输入文字和特殊按键（回车、Tab、Esc、方向键、Ctrl+字母等），用于和 REPL、全屏 TUI、确认提问交互。按键按终端当前模式编码，与用户按键走同一套编码器（`terminal.md` §9）。可以选择"发送后等待输出安静 N 毫秒（最多 10 秒）再返回屏幕内容"，免去紧接着再调一次读取。单次最多 256 项输入、文字合计最多 64 KiB，超出返回 `TOO_LARGE` |

### 3.4 SSH 后台执行

| 工具 | 级别 | 行为 |
|---|---|---|
| `kanso_exec` | 完全 | 在 SSH 会话所在的服务器上执行一条非交互命令，**不经过任何终端标签**，分别返回标准输出、标准错误和退出码 |

- 只支持 SSH 类型的会话。本地会话不提供：AI 工具本来就运行在本机，它可以直接执行本机命令；纯 SFTP 会话不开 shell 通道，服务器也常常禁止执行命令。
- 在会话的已认证连接上另开一个 exec 通道（与 `ssh.md` §10 相同的做法），不打扰用户正在用的 shell。有现成的已认证连接就复用，没有时按 §2.4 新建连接（不向用户提问）；新建的连接不在界面上显示为标签。连接的释放见 §2.4。
- 不请求 PTY，不发送 `LANG` 之外的环境变量（`LANG` 规则同 `ssh.md` §6）。命令文本原样交给服务器，由用户的登录 shell 解析。
- 超时默认 60 秒，可设 1–600 秒。超时后关闭通道并返回已收到的输出和"超时"状态，同时说明**远端进程可能仍在运行**：很多服务器不处理 SSH 的 signal 请求，关闭通道不保证结束进程。
- 同一个连接上同时进行的后台执行最多 4 个，超出的排队等待，排队时间计入超时。
- 输出不写入命令历史（`store-import.md` §5），因为它们不是用户在终端里执行的命令。

### 3.5 SFTP

适用于 SSH 和纯 SFTP 两种会话。SFTP 子系统按 `ssh.md` §7 的规则在第一次请求时打开，并与 Filer 共用。

| 工具 | 级别 | 行为 |
|---|---|---|
| `kanso_sftp_list` | 只读 | 列目录。条目字段同 `ssh.md` §8。一次最多返回 1000 条，带续页标记 |
| `kanso_sftp_stat` | 只读 | 查看单个路径的属性；可选择是否跟随符号链接 |
| `kanso_sftp_read` | 只读 | 读文件，可指定偏移和长度，单次最多 1 MiB。默认按文本返回：用会话编码转成 UTF-8，遇到无法解码的内容或 NUL 字节时报错，提示改用 base64 方式读取 |
| `kanso_sftp_write` | 完全 | 写文件，内容为文本（按会话编码转换后写入）或 base64，单次最多 8 MiB。必须指定模式：**仅新建**（已存在则失败，同 `ssh.md` §8 新建空文件）或**覆盖**。覆盖规则见下方 |
| `kanso_sftp_mkdir` | 完全 | 新建目录；可选择逐级创建 |
| `kanso_sftp_remove` | 完全 | 删除文件或空目录。**不提供递归删除**，删除非空目录需要 AI 自己逐层完成，每一步都会记进审计日志 |
| `kanso_sftp_rename` | 完全 | 重命名或移动；目标已存在时失败 |
| `kanso_sftp_download` | 完全 | 把远端文件或目录下载到本机的绝对路径，走传输队列，规则同 `ssh.md` §9（含本地路径安全检查），在界面的传输列表里可见。等传输结束（或失败、取消）后返回结果 |
| `kanso_sftp_upload` | 完全 | 把本机的文件或目录上传到远端，规则同 `ssh.md` §9.3，在传输列表里可见 |

- 远端路径可以是绝对路径，也可以是相对于 SFTP 家目录的路径。
- **覆盖写入**：
  - 先写到同目录的临时文件（以 `.` 开头、带 `kanso-tmp` 字样和随机后缀，便于识别），写完再改名替换目标。中途失败不会留下写了一半的目标文件。
  - 改名用 OpenSSH 的 `posix-rename@openssh.com` 扩展。SFTP v3 的标准 RENAME 在目标已存在时会失败（draft-ietf-secsh-filexfer-02 §6.5）。服务器没有声明这个扩展时，覆盖写入直接报 `UNSUPPORTED`，不退回到直接截断写入。
  - 目标是符号链接时，先解析出它指向的真实路径，再对真实路径做上述替换，链接本身保持不变。否则改名会把链接换成普通文件，破坏用符号链接管理的配置。
  - 保留原文件的权限位。属主和属组无法通过 SFTP 可靠地保留，以执行写入的用户为准。
  - 失败时尽量删除临时文件。连接已断开、删不掉时，在错误说明里给出临时文件路径。
- **上传与下载的同名冲突**：Filer 遇到同名文件会询问用户（`filer.md` D4），MCP 不能提问，所以改为由调用方传入冲突策略：
  - **失败**（默认）：发现第一个同名项就停止，已经传完的部分保留，结果里列出冲突项。
  - **覆盖**：同名文件直接覆盖。
  - **跳过**：同名文件不传，结果里列出被跳过的项。
  - 同名目录照 `ssh.md` §9.3 合并，其中的同名文件仍按所选策略处理。下载可以写本机任意绝对路径，默认的"失败"策略避免 AI 无意中覆盖本机已有文件（例如 `~/.ssh` 下的文件）。
- 用户在传输列表里取消 MCP 发起的传输时，调用返回"已被用户取消"。

## 4. 与用户操作的协同

### 4.1 可见性

- MCP 正在操作的标签，在标签行上显示 MCP 标识（替代或叠加在活动标识上，具体样式由 `ui-shell.md` 补充），鼠标悬停提示显示客户端名称和正在执行的操作。操作结束 2 秒后撤掉标识。
- MCP 打开的标签，在它的整个生命周期里都带一个小的"由 MCP 打开"标记，提示显示是哪个客户端打开的。
- 状态栏在有 MCP 客户端连接时显示一个指示器，显示已连接的客户端数，点击打开设置 → MCP。

### 4.2 `kanso_terminal_run` 的前置条件与完成判断

**前置条件**，任一不满足就立即拒绝并说明原因，不排队：

- 标签已连接，没有锁定（`terminal.md` §13）。
- 没有命令在运行，也没有 AI CLI 在运行（`terminal.md` §5、§6），也就是停在 shell 提示符上。
- 当前输入行是空的：用户输入到一半时，命令会被接在用户的输入后面。判断规则如下：
  - 自这个提示符出现以来，没有收到用户来源的输入，就算空的。用 Ctrl+C 放弃的行，以及 MCP 自己的输入，不算用户输入。
  - 有 OSC 133 B 时，还要求光标停在输入起点上。
  - 不看屏幕上输入起点之后的文字：zsh 等 shell 的自动建议会在那里显示灰字，但并不是用户的输入。
- 没有 ZMODEM/XMODEM 传输，也没有 Sender 正在向这个标签发送多行内容。
- 不是客户端所在标签（§2.5）。
- 没有另一个 MCP 调用正在操作这个标签。同一个标签同一时刻只允许一个 MCP 写操作，包括来自不同客户端的调用。

**执行与完成**：

- 发送前按 `terminal.md` §5.3 登记"即将发送某条命令"，以当前提示符作为完成特征，与 Sender 用的是同一套机制；发送失败时撤销登记。
- 命令文本只能是一行可打印文字：含任何控制字符（C0 控制字符 U+0000–U+001F，包括制表符、回车、换行、ESC，以及 DEL）一律拒绝（`INVALID_ARGUMENT`），提示按键改用 `kanso_terminal_send`、多行脚本改为逐条执行。行尾由 App 追加回车。
- 命令会进入 shell 自己的历史和 Kanso 的命令历史，与用户亲手输入的命令一样。
- 等到提示符再次出现即视为完成。有 OSC 133 D 时返回退出码，没有时退出码为"未知"。
- 超时默认 30 秒，可设 1–600 秒。超时后**不发送 Ctrl+C**，返回已有的输出和"未确认完成"状态，标签保持原样；AI 可以接着用读取工具查看，或用 `kanso_terminal_send` 发 Ctrl+C。
- 超时那一刻无法区分"命令还在运行"和"命令已经结束但没有识别出来"，所以只报"未确认完成"，不报"仍在运行"。标签没有 OSC 133 时，在说明里补充：完成判断依赖提示符特征，`cd` 等会改变提示符的命令可能导致识别不到；SSH 会话建议改用 `kanso_exec`。

**输出范围**：从命令所在行之后到新提示符之前的内容，取自屏幕和回滚。期间如果发生了清屏，只返回清屏后的部分，并注明。

### 4.3 用户接管

- MCP 的写调用（`terminal_run`、`terminal_send` 的等待阶段）进行期间，用户在这个标签里按键或粘贴，视为**用户接管**：调用立即结束，返回"用户接管"和已有的输出。用户的输入照常发给终端，不被拦截。
- 用户接管后，这个标签 10 秒内拒绝新的 MCP 写操作，避免 AI 立刻重试、和用户抢着输入。
- 终端自己的回应（`terminal.md` §5.2）不算用户按键。

### 4.4 中断

以下情况，正在执行的调用立即结束并返回对应错误：总开关被关闭、会话被降级到不足以执行该调用的级别、标签被关闭、会话断开或被锁定、客户端断开、App 退出。

- 客户端断开时，后台执行的通道随之关闭；正在进行的上传下载**继续完成**，与用户发起的传输一样留在传输列表里，由用户决定是否取消。
- 客户端按 MCP 规范发出取消通知时，按超时处理（停止等待，不对远端发送中断）。

## 5. 输出处理

- **终端内容**取自终端网格，即用户看到的文字：已经按会话编码转换，不含控制序列，宽字符只算一次，行尾多余的空格去掉，软换行的行拼回一整行。
- **后台执行和 SFTP 文本**：按会话编码转换成 UTF-8；后台执行的输出去掉 ANSI 控制序列。
- **大小上限**：单次结果中，终端文本和后台执行的每路输出最多 256 KiB。超出时保留**末尾**的 256 KiB（命令输出的结论通常在后面），并在结果里注明截断及原始大小。
- Kanso **不过滤**输出中的敏感信息，依靠授权级别控制暴露范围（§2.1）。
- 返回给 AI 的错误说明和状态文字统一用英文，并带错误码（§9）。它们是给 AI 看的协议内容，不属于界面文字，不进本地化目录。

## 6. 活动记录（审计日志）

界面上叫"MCP 活动记录"：AI 工具通过 MCP 做过的每一次操作，供用户事后核查。它不是配置项。


- 每次工具调用记一条：时间、客户端名称、MCP 会话编号、工具名、目标会话和标签、参数摘要、结果（成功 / 错误码）、耗时、返回的数据大小。
- 参数摘要包括命令文本和路径，**不记录**写入的文件内容，也不记录终端输出、后台执行输出和读到的文件内容。命令文本本身可能含敏感信息，它的敏感程度与命令历史相同（`store-import.md` §1）。
- 被拒绝的调用（未授权、前置条件不满足）也要记录，便于用户发现 AI 在尝试越权。会话为"关闭"级别时，日志里记下会话 id，界面上显示为"未授权的会话"。
- 保留 30 天且最多 10000 条，先到者为准。用户可以在活动记录窗口里一键清空。活动记录不进入 `.kanso` 导出文件。
- 日志保存在本机数据库里；系统日志（`architecture.md` §13）只记录连接、断开和错误，不记录命令文本。

## 7. 界面

本节描述 macOS 版。Windows / Linux（GPUI）版目前仍是旧布局（设置页列出会话授权与审计日志），待后续对齐。

MCP 的界面分三处：设置里管**开关与接入**，**授权跟着会话走**，**活动记录是单独的窗口**。

### 7.1 设置 → MCP

- 总开关，旁边一句说明：开启后，本机的 AI 工具可以访问已授权的会话。
- `kanso-mcp` 路径，以及客户端下拉选择（Claude Code、Codex）、对应的一条完整接入命令和「复制命令」按钮。命令可选中复制，显示与按钮复制的内容一致（`claude mcp add …` / `codex mcp add …`），命令里带客户端令牌，以一个空格开头；切换客户端或重新生成令牌后，显示和复制的命令同步更新。
  - 开头的空格让命令不进入 Kanso 自己的命令历史（terminal.md §5.2），但**挡不住 shell 自己的历史**：macOS 默认的 zsh 没有开启 `HIST_IGNORE_SPACE`，令牌会写进 `~/.zsh_history`。
  - 按钮旁用一句话说明："命令里含有令牌，可能被记入 shell 历史；介意的话可在执行后清理历史，或重新生成令牌。"
  - 不为此改用令牌文件等方案：令牌本来就以明文写在 AI 工具的配置文件里，多一份 shell 历史并不实质降低安全性（§1.1）。
- 重新生成客户端令牌（§1.1）。
- **已连接的客户端**：名称、连接时间、调用次数；每个客户端可以单独断开。
- 一行只读说明：已授权的会话数，以及"可在会话列表的'…'菜单或会话编辑对话框中修改"；一个都没有时说明"还没有授权任何会话"。设置页不列出会话、不在这里改级别。
- "打开活动记录"按钮（§7.3）。

### 7.2 会话授权

授权是会话自己的属性，在会话所在的地方配置；会话再多也不会把设置页撑长。

- **会话编辑对话框**（`ui-shell.md` §5）："MCP 访问"字段（关闭 / 只读 / 完全）。新建默认"关闭"；从"关闭"调高时字段下方显示敏感内容提示（§2）。
- **会话启动器**（`ui-shell.md` §4）：
  - 每个会话的"…"菜单有"MCP 访问"子菜单（关闭 / 只读 / 完全，当前级别打勾）。从"关闭"调高时先弹一次确认，说明 AI 能看到终端内容和命令、其中可能有敏感信息；取消则不改。
  - 每个分组的"…"菜单有"MCP 访问 ▸ 整组设为…"：一次性把组里每个会话设成同一级别（从"关闭"调高同样先确认；作用于整个分组，不受搜索过滤影响）。授权仍然落在每个会话上，之后加入该分组的会话不会自动继承。
  - 级别不是"关闭"的会话，行尾显示一个小的 MCP 标记，悬停显示级别；点击标记等同点击该行。
- 以上入口读写同一份数据，改动立即生效（§2）。MAS / Setapp 版都不显示。

### 7.3 活动记录窗口

- 独立窗口"MCP 活动记录"，入口：菜单栏"窗口 → MCP 活动记录"、点击状态栏的 MCP 指示器、设置页的"打开活动记录"按钮。同一时间只有一个窗口，再次打开时前置已有窗口。关闭主窗口退出 App 时它一并关闭。
- 顶部一句说明："AI 工具通过 MCP 进行的每次操作都记在这里，只保存在本机，保留 30 天。"
- 列表按时间倒序：时间、客户端、工具、目标会话、结果（失败时显示错误码）；失败记录的目标会话当前为"关闭"级别时显示为"未授权的会话"。可以按客户端、会话、"只看失败"筛选，"更多"加载下一页；"清空"放在角落，清空前确认。
- 服务端每批记录落库（或清理删除了旧记录）后通知界面。窗口可见、停在第一页时自动重载第一页（沿用已提交的筛选）；已经翻过页时不打断，只显示"活动记录有变化，点击刷新"。
- MAS / Setapp 版没有这个窗口和菜单项。

## 8. 安全要求

- 连接必须带有效的客户端令牌（§1.1）。
- `kanso-mcp` 与 App 之间的本机通道**只允许当前用户连接**。Unix 赋予当前用户访问 socket 目录和文件的权限，Windows 命名管道仅允许本机当前用户的 SID。App 在接受连接时再次核对对端身份。
- `kanso-mcp` 本身不读取数据库、钥匙串和私钥文件，也不发起任何网络连接；所有操作都由 App 执行，授权检查也只在 App 里做。
- 单条消息最大 16 MiB，超出的消息被丢弃（由 MCP SDK 的传输层处理），不影响该连接的其他消息（`kanso_sftp_write` 的 8 MiB 上限加上 base64 膨胀仍在此范围内）。
- 授权检查在**每次调用时**进行，不在连接时缓存结果。

## 9. 错误

每个错误带一个稳定的错误码和一句英文说明，供 AI 判断下一步：

| 错误码 | 含义 |
|---|---|
| `MCP_DISABLED` | 总开关关闭 |
| `INVALID_TOKEN` | 客户端令牌缺失或不匹配（§1.1），在初始化时返回 |
| `NOT_RUNNING` | Kanso 没有运行，由转发程序返回 |
| `TOO_MANY_CLIENTS` | 同时连接的客户端超过上限 |
| `VERSION_MISMATCH` | 转发程序与 App 版本不一致，需重启 AI 工具或更新 Kanso |
| `NOT_FOUND` | 会话或标签不存在、已关闭，或会话级别为"关闭" |
| `ACCESS_DENIED` | 会话级别不足以执行该操作 |
| `TAB_BUSY` | 标签不满足 §4.2 的前置条件，说明里写明是哪一条 |
| `TAB_SELF` | 目标是客户端所在标签（§2.5） |
| `USER_TOOK_OVER` | 用户接管（§4.3），或在接管后的 10 秒内 |
| `NEEDS_USER` | 新建连接时认证需要人参与（§2.4），需要用户先在 Kanso 中打开该会话 |
| `NOT_CONNECTED` | 会话的访问级别为只读，而且没有可用的连接（§2.4） |
| `CONFLICT` | 传输遇到同名项且策略为"失败"（§3.5） |
| `TIMEOUT` | 等待超时，结果里仍带已收到的输出；`kanso_terminal_run` 超时时表示"未确认完成"（§4.2） |
| `CANCELLED` | 被用户取消（传输列表）或被客户端取消 |
| `INTERRUPTED` | §4.4 中的其他中断 |
| `UNSUPPORTED` | 会话类型不支持该操作（例如本地会话调用 `kanso_exec`） |
| `TOO_LARGE` | 请求或单次读写超过上限 |
| `INVALID_ARGUMENT` | 参数不合法：例如 `kanso_terminal_run` 的命令含控制字符（含换行）、`kanso_terminal_send` 的按键名无法识别；不会触达终端，AI 应修正参数而不是重试 |
| `REMOTE_ERROR` | SSH 或 SFTP 返回的错误，说明里带服务器给的原始信息 |
| `CONNECTION_FAILED` | 连接失败，说明沿用 `ssh.md` §11 的错误分类 |

## 10. 不在第一版范围内

- HTTP 传输（§1）。
- MCP 的 resources、prompts、sampling 能力；只提供 tools。
- 本地会话的后台执行（§3.4）、SFTP 递归删除（§3.5）。
- 让 AI 修改会话配置、分组、Sender 命令或设置。

## 11. [MAS] 与 Setapp

- **Setapp**：没有沙盒，技术上和 Direct 相同；等 Setapp 版启动时，确认 Setapp 的审核要求后再开放。
- **[MAS]**：待实测。疑点有：沙盒内的 App 能否在容器外建立可供外部程序连接的本机通道；外部 AI 工具能否执行 App 包内的 `kanso-mcp`（它同样受沙盒约束，需要和 App 共享 App Group 容器才能找到通道）；审核能否接受。实测前商店版不提供此功能，设置里不显示 MCP 页面。

## 12. 验收用例

1. Kanso 运行、总开关关闭时，AI 工具启动 `kanso-mcp` 收到"MCP is disabled"错误；Kanso 未运行时收到"Kanso is not running"错误，且 Kanso 没有被拉起。
2. 不带令牌、带错误令牌的连接都收到 `INVALID_TOKEN`，并在审计日志里留下记录；重新生成令牌后，用旧令牌建立的连接立即断开，用新令牌可以连接。
3. 三个会话分别设为关闭、只读、完全：`kanso_list_sessions` 只返回后两个；对只读会话调用 `kanso_terminal_run` 返回 `ACCESS_DENIED`；对关闭会话的任何调用返回 `NOT_FOUND`，与真的不存在无法区分。
4. 调用正在执行时把会话从完全降为只读，调用以 `INTERRUPTED` 结束；之后的写调用返回 `ACCESS_DENIED`。
5. 导入一个含会话的 `.kanso` 文件，导入的会话级别都是"关闭"；导出文件里没有任何 MCP 相关字段。
6. 在空闲的 SSH 标签上 `kanso_terminal_run` 执行 `ls`，返回目录列表；有 OSC 133 的本地标签同时返回退出码。
7. 标签里有一个 `sleep 100` 在运行时，`kanso_terminal_run` 立即返回 `TAB_BUSY`；用户在输入行里已打了半条命令时，同样返回 `TAB_BUSY`，用户的输入不受影响。
8. `kanso_terminal_run` 执行 `sleep 100`，超时 5 秒：返回 `TIMEOUT` 和"未确认完成"，标签里的命令继续运行，没有收到 Ctrl+C。
9. `kanso_terminal_run` 等待期间用户在该标签按键：调用返回 `USER_TOOK_OVER`；10 秒内对该标签的写调用都返回 `USER_TOOK_OVER`，10 秒后恢复。

11. `kanso_exec` 对一个没有打开标签的 SSH 会话执行 `uname -a`：返回标准输出和退出码 0，界面上没有出现新标签；5 分钟后连接断开（自建连接）。期间用户打开该会话的标签，连接被共享；关闭标签后连接仍保持到 5 分钟期满。

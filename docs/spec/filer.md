# Filer 规格

覆盖本地与远端文件浏览、文件操作、上传下载入口、拖放、本地编辑器编辑远端文件，以及 Git 改动面板。

核对基准为 2026 年 11 月 14 日旧仓库的当前工作副本，包括当时已有的未提交改动；同时核对相关历史修复说明和已有测试的断言。这里记录行为，不保留旧实现的内部名称、组织方式或实现步骤。本次未运行真实服务器传输、Finder 拖放或沙盒发行版；文末用例是新版应满足的验收条件，不表示已经实测通过。

未特别注明的条目为新版需要保留的行为。标“旧版”的段落说明已核对的现状；标“新版新增”或“新版改为”的条目说明相对旧版的变化及理由。**[待定]** 表示还需要产品决定，不应当成已经具备的能力。

## 1. 面板、入口和会话关系

### 1.1 位置与宽度

- Filer 是位于竖向标签栏与终端分屏区之间的可收起辅助面板（与旧版相同，参考 `docs/design/reference/filer.png`），开关为 ⌘⌥→；其他平台的对应键及重新绑定规则见 ui-shell.md §7。视图菜单与状态栏的“文件浏览器”操作同一个面板。
- 位置以 ui-shell.md §1 为准：Filer 在终端左侧，Git 改动面板在终端右侧。（产品决定，2026-11-14：沿用旧版布局，撤销此前“改到右侧”的设想。）
- 宽度可拖动调整。旧版初始宽度为 320 个逻辑像素，允许在 220–560 之间调整；同一窗口存活期间保留调整后的宽度。新版保留这一可用范围，在窗口不足以容纳时优先保证终端仍可操作。
- 旧版保存显隐状态，不保存宽度。**新版新增：重启后恢复宽度和显隐**，遵循 ui-shell.md §1，避免每次重新整理工作区。
- 关闭面板只改变显示。**新版改为：收起、切换显示位置或移到另一个分屏，不中断已经开始的传输和远程编辑同步**，遵循 ui-shell.md §3。

### 1.2 跟随哪一个会话

- 面板显示当前活动标签的文件；有多个分屏时，以最后获得焦点的那个分屏里的活动标签为准，不同时展示所有分屏的文件。
- 本地 shell 标签浏览本机文件；已连接的 SSH 标签浏览该连接对应的远端文件。切换显示对象不执行 shell 命令，也不改变任何 shell 的工作目录。
- 远端文件操作使用选中标签的连接。两个标签即使使用同一个已保存配置，也仍是两个活动会话；不能仅凭相同主机名称混用它们的浏览位置、传输反馈或编辑状态。**新版新增：在面板标题或路径旁明确显示“本地”，或远端会话名称与主机地址**，因为只看目录文字不足以判断操作对象。
- **新版改为：SSH 断线后保留远端身份、最后目录和标为过期的列表，显示“连接已断开”，停止远端写入操作。** 旧版会退回本地文件来源；不能保留这种表现，否则同样的路径文字可能被误认为仍属于服务器。
- 连接中显示连接状态；连接失败显示对象和原因；重连成功后重新读取当前远端目录，目录失效时保留错误和导航入口，允许回到远端家目录。

### 1.3 浏览位置的记忆

- 旧版辅助面板的本地标签共用一个浏览位置；切换远端会话会回到家目录，收起后重新打开也可能重新定位，并没有完整的“每标签最后目录”记忆。
- **新版新增：在活动会话存活期间，分别记住每个标签的最后成功目录。** 切到别的标签再回来，恢复自己的目录；同一个标签在分屏间移动也保留，原因是用户手动浏览的位置不能被切换标签丢掉。
- 第一次打开时，用户主动定位得到的目录优先；没有定位请求时，本地从本机家目录开始，SSH 从远端家目录开始。远端家目录的定义见 ssh.md §8。
- ⌘J 和“定位终端目录”明确覆盖该标签记住的浏览位置；shell 后来自行切目录，不持续带动 Filer。
- **[待定 D1]** 是否在应用重启、关闭后重新打开会话时恢复最后目录。旧版没有这项保证；决定前只要求活动会话内记忆，不把浏览位置写成已保存连接的起始目录。

### 1.4 纯 SFTP 标签

- 纯 SFTP 会话的主工作区直接显示双栏文件浏览器，不显示终端，连接生命周期见 ssh.md §7。
- 旧版左栏为远端、右栏为本地，中间提供上传和下载按钮。两栏分别有标题、位置说明、路径栏、家目录、上一级和刷新；首次连接各自定位到自己的家目录。
- 两栏分别保留浏览位置和单选项，切换标签只隐藏该工作区。重新连接会重新读取目录；旧版重连时回到两端家目录。
- 辅助 Filer 在纯 SFTP 标签里不再重复显示；状态栏“文件浏览器”置为不可操作，并说明文件浏览已经在当前标签打开。面板开关键也不额外展开一栏。
- 双击目录进入；旧版双栏中双击普通文件不打开编辑器，也不自动下载。双栏操作范围的其他差异见 §5、§6；不能把辅助 Filer 的所有菜单默认套到双栏上。

## 2. 定位 shell 工作目录

⌘J、终端右键菜单的“在 Filer 中显示工作目录”和面板内的“定位终端目录”必须执行同一个用户动作。旧工作副本暂停了全局 ⌘J，终端右键菜单也暂时没有这个入口；**新版恢复两者**，以 ui-shell.md §7 和 terminal.md §8 为准。

1. 锁定用户发起操作时的标签和本地／远端身份。只对仍连接的本地 shell 或 SSH shell 定位；纯 SFTP 没有 shell 工作目录，无活动标签时不执行。
2. 取得该 shell 的真实目录。上报优先级见 terminal.md §12；本地查询见 local-shell.md §6，远端查询见 ssh.md §10，不重复定义另一套规则。
3. 成功后展开 Filer，直接读取目标目录，路径栏显示成功读取后的完整目录，不先显示家目录再跳转。**必须做到这一点，因为家目录读取和定位请求竞争会让面板最后停错地方。**
4. 状态栏提示已定位的位置。重复请求同一路径仍应重新读取，不因路径文字没变而忽略刷新；定位只执行一次，不改成持续轮询。
5. 取得目录失败时，在状态栏给出对象和原因，不擅自用家目录或先前目录充当结果。远端失败文案遵循 ssh.md §10；会话未连接时说明“会话未连接”，纯 SFTP 则说明“文件会话没有 shell 工作目录”。
6. 目录取得成功但无法列出时，展开面板并显示该目录的读取错误；最后成功的列表可以保留，但必须标明它仍属于原目录，不能把旧条目挂在新的路径文字下面。

**新版改为：过时的定位结果不得作用于后来切换到的标签。** 请求期间切换标签或关闭原标签时，只能更新仍存在的原会话，不能让后返回的结果抢走当前面板。通过本地 shell 手工登录另一台机器后，远端上报的目录也不能被误当成本机目录；无法确认属于当前文件来源时解释原因，不在错误机器上尝试操作。

状态栏“文件浏览器”在已展开时立即收起；在隐藏时先尝试显示当前 shell 目录，成功后展开。用户通过视图菜单单纯展开面板时可以使用已记住的浏览位置。前者是“看当前终端位置”，后者是“继续浏览”。

## 3. 路径与目录导航

- 路径栏是可编辑的完整路径文本。输入后按 Enter 请求打开，按 Esc 放弃输入并恢复最后成功目录；只是修改文字时不发出目录请求。
- 成功进入目录后，用实际可访问的规范路径更新路径栏。路径规范化与远端列举的共用语义见 ssh.md §8。
- 本地支持家目录缩写；远端旧版不专门展开家目录缩写，不承诺由本地 shell 解释远端路径。**新版改为：相对路径以当前浏览目录为基准**，避免相对于应用启动位置而跳到无关目录；绝对路径保持原意。
- 上一级在远端根目录和 Unix 本地根目录停在根目录。Windows 盘符根目录的上一级为“此电脑”，再向上仍停在此处。
- 刷新读取当前浏览目录，保留路径；成功后重置旧选项，防止后续下载或删除仍指向已经消失的条目。
- 旧版辅助 Filer 没有单独的家目录按钮，双栏两边都有。**新版新增：辅助 Filer 也提供回到当前来源家目录的入口**，因为没有 shell 的位置可用时仍需要一个可靠的导航起点。
- 旧版没有可点击面包屑、前进／后退历史或目录收藏。它们不属于现有行为。
- **[待定 D2]** 浏览增强是否纳入首版：可点击面包屑、隐藏文件开关、数字自然排序、可切换排序列。决定前保持直接路径输入、全部条目可见和 §4.1 的固定排序；不能在没有入口时暗中隐藏条目。

## 4. 列表、加载与异常

### 4.1 列和排序

- 辅助 Filer 显示名称和修改日期两列。修改日期按本地时区显示年、月、日；旧版不显示时分。文件大小和其他属性放在悬停说明中，不额外冒充已有的大小列。
- 纯 SFTP 双栏显示名称、大小、修改时间三列；目录大小显示破折号，修改时间包含本地化的日期和时分。
- 两种列表都先列目录，再列其他条目；每组按名称忽略大小写做字典序升序，数字作为普通文字比较，**不是数字自然排序**。旧版没有点击列标题切换排序。
- 旧版大小写折叠后相同的名称按原列举次序保留。**新版新增：忽略大小写比较相同时，再按原名称的字符顺序升序排列**，避免刷新后无理由跳动；这不意味着大小写不同的文件可以视作同一个文件。
- 旧版没有隐藏文件过滤，两种列表都展示列举出的隐藏项。刷新、改变主题和切换标签不得改变这一默认规则。
- 没有值的修改时间、大小、权限或属主应显示未知或留空。**新版改为：读取不到元数据不显示为真实的零字节文件**，因为“未知”和“空文件”会影响用户判断是否下载成功。

### 4.2 图标、属性和条目统计

- 文件夹和文件有不同图标；常见文件类别可按名称或扩展名区分。图标匹配忽略大小写，更具体的多段扩展名优先；没有合适图标时使用通用图标。浅色和深色主题均须清楚可辨。
- 图标资源使用许可允许的来源，具体图案不属于本规格。图标尚未出现时保留位置，不能让名称列反复左右移动。
- 辅助 Filer 悬停显示完整路径、文件／目录／链接类型；普通文件附带易读大小；有权限时显示八进制权限，有属主和属组时一起显示，缺失属性不编造。
- 辅助 Filer 底部按目录、普通文件、符号链接分别计数，链接不在普通文件中重复计数；空目录显示零项。双栏底部各显示本栏条目总数和目录／加载状态。
- **必须做到同类图标不会随每一行重建反复加载，因为旧版大目录曾因此明显停顿。** 图标加载失败不能阻止名称和文件操作使用。

### 4.3 加载与刷新

- 旧版两种列表都等待完整目录读完后一次显示，辅助 Filer 底部提示“处理中”，双栏在列表和底部提示“加载中”。
- **新版改为：大目录分批出现，加载未完时持续显示正在读取，完成后才给出最终条目数**；远端要求已经由 ssh.md §8 确定，本地也保持相同的可用体验。列表可滚动，不能等待全部图标和全部元数据才允许看到首批名称。
- 分批显示仍遵守目录在前、名称排序；当后续批次插入前面的条目时，保留用户正在看的条目和选中对象，不把单击落到另一行。
- 多次快速导航只采纳最后一次请求的显示结果；来自旧目录、旧标签的成功、失败和“加载完成”都不能覆盖新目录。
- 目录读取中的状态与文件传输中的状态应区分。正在读目录时不允许使用旧条目发起删除等写入；传输本身不阻塞终端，见 ssh.md §9。
- 旧版没有持续监控目录外部变化。创建、删除、重命名和上传成功后刷新受影响列表；下载到双栏本地目录后刷新本地栏；外部程序改变文件后可手动刷新。远程编辑同步完成后的目录属性刷新见 §9。

### 4.4 符号链接和读取失败

- 链接必须可辨认。旧版辅助列表用不同名称颜色和“链接”属性表示；双栏没有独立链接操作菜单。
- 旧版是否可双击进入链接到的目录，取决于列举结果是否把该条目标成目录；没有主动识别目标的完整保证。**新版改为：用户激活链接时确认目标类型；指向可读目录则进入，指向普通文件则按文件打开，悬空或不可访问时说明原因。** 浏览中的跟随链接与目录传输的链接策略是两回事，传输遵循 ssh.md §9。
- 删除链接只删除链接本身，不删除它指向的文件或目录。不得因为浏览时跟随了链接，就把“删除链接”变成“删除目标”。SFTP 的链接与移除语义出处见 §12 的 SFTP 资料。
- 权限不足、目录不存在、路径实际是文件、磁盘不可用、服务器读取失败应分别给出可理解的原因，附带正在访问的目录及本地／远端身份，不能显示成空目录。
- macOS 用户刚接受“文件与文件夹”访问授权时，旧版会短暂重试权限拒绝；新版本也必须在授权生效后可刷新成功，无需重启。不能对目录不存在等其他错误无限重试。
- 已经列举到名称但个别属性暂时取不到时，名称仍应可见，属性标未知；**不能悄悄丢掉所有条目后告诉用户目录为空**，这是旧版处理权限切换时积累的经验。

## 5. 选中、菜单和文件操作

### 5.1 选中与键盘

- 旧版两种浏览器都是单选；普通单击选一项，右键行先选中该行再打开菜单。辅助 Filer 双击目录进入，双击文件用本地应用打开；双栏双击只进入目录。
- 旧版没有连续范围选择、⌘／Ctrl 多选、列表内全选或批量删除，也没有成套的方向键导航、F2 重命名、Delete 删除快捷键。终端的全选命令不应被描述为文件多选。
- 路径输入的 Enter／Esc、新建名称的 Enter／Esc，以及删除确认的 Enter／Esc 是旧版实际具备的局部按键行为；全局 Filer 按键见 ui-shell.md §7。
- **[待定 D3]** 是否增加文件多选、批量操作、完整列表键盘导航及辅助 Filer 的重命名入口。旧版重命名只在纯 SFTP 双栏工具条里提供，不能宣称辅助 Filer 已支持就地重命名。若统一这些入口，需要同时确定批量确认和同名目标规则；在决定前保留单选和双栏重命名。

### 5.2 辅助 Filer 的完整入口

工具条包括：新建文件、新建目录、上传菜单、下载选中项、刷新、删除选中项。没有远端连接时上传、下载仍可见但不可用，提示只适用于已连接的 SSH；未选择条目时下载和删除不可用。Windows“此电脑”等虚拟位置不能新建或删除。

文件行的右键菜单，按以下顺序提供：

- 打开；普通文件额外有“打开方式”。
- 下载；只对远端条目提供，目录也可下载。
- 复制完整路径、复制名称。
- 删除，带危险操作样式和确认。

目录行没有“打开方式”，其“打开”表示进入目录。列表空白处的右键菜单为：

- 新建文件、新建目录。
- 上传文件、上传目录；只对远端显示。
- 复制当前目录路径。
- 刷新。

上传工具条按钮展开的是同一个“上传文件／上传目录”选择，再点按钮可以收起。菜单不应超出窗口右边界而变得无法点击。复制路径、名称使用原文字；复制失败必须显示错误，不能表现为成功。

旧版没有“在终端切换到这里”“向终端插入路径”“在 Finder 中显示”、文件剪切／粘贴、权限编辑、属主编辑或批量移动菜单。这些不应作为既有入口交给新版实现者。

### 5.3 新建与重命名

- 辅助 Filer 新建项在列表顶部出现名称输入，立即获得焦点。Enter 或失焦提交，Esc 取消；空名称不创建。首尾空白在旧版会去掉。
- 名称必须是当前目录的一个直接子项，不能是当前目录、上一级或带目录分隔符的路径。已有同名项时显示“已经存在”；并发创建的保护及远端空文件语义见 ssh.md §8。本地新建同样不得清空已有内容。
- 提交成功刷新当前目录；失败显示名称与原因，旧版不保留失败的输入行。
- 双栏各有新建目录、重命名、删除按钮，没有新建空文件入口，也没有辅助列表那套右键菜单。
- 双栏重命名用弹出的名称输入框，预填旧名称；取消、空名称或未更名时不执行。成功后刷新本栏，失败留在本栏解释原因。
- **新版改为：双栏名称输入也限制为直接子项**，不能把重命名输入当成跨目录移动路径；否则两个看似相同的名称输入入口会具有不同的破坏范围。
- 旧版重命名没有统一的同名冲突确认，本地和远端可能因文件系统／服务器语义得到不同结果。新版统一策略尚待 §6.3 决定，不应承诺各平台都覆盖或都拒绝。

### 5.4 删除确认与不可撤销性

- 删除是永久移除，旧版不进废纸篓，不支持撤销，不递归删除非空目录。非空目录应保留并提示只能删除空目录。
- 辅助 Filer 确认框显示“删除文件／删除目录／删除链接”、名称、完整路径和所在本地或会话名称。普通文件说明“文件将被移除，无法撤销”；目录说明“只能删除空目录，无法撤销”；链接说明“只移除链接，不影响目标，无法撤销”。
- 确认框中 Enter 确认，Esc 或取消按钮取消；点击框外取消。必须先把焦点移入确认框，避免一次操作同时送到名称输入或终端。确认后只执行一次。
- 双栏旧版使用较简单的系统确认：远端提示是否删除所选项，本地提示删除文件或空目录。**新版改为：两种界面都清楚展示本地／远端身份、路径及不可撤销说明**，因为主机名相同或目录名称相同时只显示名称容易误删。
- 删除成功刷新，失败保留原项和错误。删除对象在确认期间已经消失时显示其已不存在，不错误地作用于后来占用同一列表位置的另一项。

## 6. 上传、下载、冲突和传输反馈

### 6.1 入口与目标

- 辅助 Filer 的上传菜单或空白处菜单可以通过系统选择器多选本地文件，或多选本地目录；也接受 Finder 等文件管理器拖入，见 §7。
- 上传到当前显示的远端目录，保留每个所选项自身的名称。接收任务时锁定远端会话和目标目录；用户随后切标签或导航不得改写已开始任务的目的地。
- 下载来自工具条的选中项按钮或条目右键菜单。普通文件弹出系统保存选择器，以远端名称作为默认名称，允许用户更名；目录让用户选择父目录，在该位置下保留远端目录名称。取消选择器不创建任务。
- 双栏上传将选中的本地项送入当前远端目录；下载将选中的远端项放入当前本地目录，不再弹出目标选择器。传输完成后刷新接收侧。
- 上传下载的文件、目录、链接和特殊文件处理及路径安全都遵循 ssh.md §9；这里的入口不能绕过那些规则。

### 6.2 排队、取消和结果

- 辅助 Filer 一批选择多个源项时按顺序逐项处理，每次只显示正在处理的那一项。目录内部传输规则见 ssh.md §9；不得把多个文件同时传输误写成旧版已有的能力。
- 同一浏览器已有前台传输或复制时，不再接收另一批；拖入时明确提示“正在处理，请等待当前传输完成”。旧版没有可编辑的全局任务队列，也没有统一的跨标签并发数承诺。
- 当前项失败或取消时，停止这批余下项目；已完成项保留，刷新接收侧以显示已经到达的内容。不能自动重新开始被用户取消的这一批。
- 辅助 Filer 底部显示方向／操作、当前名称、进度条、已传字节、总字节及速率。总量未知时显示不确定进度，不能把零总量显示成“传完了”。完成时显示 100%。
- 速率反映最近约一秒的传输速度，不是从任务建立开始计算的终身平均值。复制、上传、下载、准备拖出、远程编辑保存回传使用不同文字，避免用户分不清正在做什么。
- 可取消的传输显示取消按钮；按下后显示“已取消”，不当作普通失败。取消后清理的实际要求见 ssh.md §9.1。旧版本地复制与自动编辑回传没有取消按钮。
- 旧版纯 SFTP 双栏显示方向、名称、字节和进度，完成／失败状态保留到下一项；没有速率，也没有取消按钮。**新版新增：双栏同样可取消上传下载**，因为共用传输已承诺可取消，不能让长目录传输在一个入口无法停止。
- 辅助 Filer 完成或取消约 1.8 秒后恢复条目统计，失败进度约 3 秒后收起；详细错误仍留在错误区域直到下一次操作清除。新版不得在短提示消失时一并丢失失败原因。
- 旧版没有传输完成的系统通知、声音或任务历史。完成反馈在文件界面内；不把桌面通知描述为已有功能。
- **新版改为：传输反馈始终可归属到原会话、原目录和原项。** 远程编辑可能在后台回传，不能覆盖另一个标签的上传进度并让用户误以为它已经结束。

### 6.3 同名冲突：旧版边界与待定策略

旧版入口并不一致：

- 辅助 Filer 上传和本地拖入复制没有应用内覆盖确认；普通同名文件可能被覆盖，同名目录合并，其内部同名文件也可能被覆盖。
- 普通下载使用系统保存选择器，其覆盖确认由平台提供；目录下载只选父目录，没有对目录内每个同名文件逐一询问。
- 双栏传输先检查目标栏已列出的同名项：文件与目录类型冲突时报错；同名文件询问是否替换；同名目录询问是否合并，并明示同名文件会被替换。拒绝确认不发起传输。
- 双栏下载明确拒绝替换本地符号链接。目录接收的其他目标安全约束见 ssh.md §9，不能只靠界面里可能已经过时的列表判断。
- 旧版没有“跳过”“自动重命名”“全部应用”的完整冲突对话框；系统保存选择器里的更名也不等于整批传输具备自动重命名策略。

**[待定 D4] 新版统一的同名冲突产品策略。** 需决定上传、下载、本地复制与重命名各自的默认行为，以及是否提供“覆盖／跳过／更名／取消”和“应用于本批其余冲突”。目录应明确区分合并与整目录替换，不能把旧版合并解释成删除接收侧多余内容。决定前保留上述入口差异，不宣称已经有统一冲突保护；任何新策略都要对传输开始后才出现的同名项生效。

## 7. 拖放

### 7.1 从文件管理器拖入

- 外部拖入可以包含多个文件和目录；远端 Filer 将它们上传到当前远端目录，本地 Filer 则复制到当前本地目录，保留源项。拖入目录的内容处理引用 ssh.md §9，不因入口是拖放而改变。
- **整个辅助面板都是落点**，包括路径区、列表和底部，不只列表中间的一小块。落到某个目录行上，旧版仍写入当前显示目录，不自动写入该行目录，也不悬停自动进入。
- 鼠标在可接受范围内时高亮面板，底部说明“放下以上传”或“放下以复制到这里”；离开、取消、放下后清除高亮。
- 没有打开目录、正在处理其他任务、停在 Windows“此电脑”等不可写位置时，显示不可接受样式和具体原因；真正放下时也要给出原因，不能无声忽略。
- **必须按用户真正松手的位置区分文件面板、各个终端分屏和覆盖其上的对话框。** 在 Retina 或其他缩放显示器上不能把位置错误缩小，旧版曾因此把落点算到面板左边，用户看见拖入却完全没有上传。
- 旧版双栏工作区没有这套拖入／拖出入口。新版暂不把双栏区域显示为可接收落点，除非另外补齐目标与反馈约定；多文件上传仍可从辅助 Filer 的系统选择器发起。

### 7.2 本地条目拖出

- 从辅助列表按住左键移动超过约 5 个逻辑像素才进入拖动，轻点只选择，不能误触发文件复制。
- 本地文件或目录本身已经存在，可直接交给系统拖放，用户能放到 Finder、桌面或接收文件的其他应用。
- 本应用不因开始拖出就删除、移动或另存本地源文件；外部接收者最终如何处理文件，遵循它接受的系统拖放操作。这里只承诺源项能作为文件交付，不承诺每个其他应用都接受。
- 拖动源项有正在拖动的视觉反馈；开始失败显示名称和原因。鼠标快速越出行的范围仍能启动拖动，不能要求一直压在原来那一行。

### 7.3 macOS 远端条目拖出：file promise

- 远端文件还不存在于本地，因此向系统提供“用户放下后再交付文件”的承诺。文件与目录均支持，拖到 Finder 或桌面后，由接收方确定完整本地落点。
- **只有接收方接受并要求交付时才下载，直接下载到所给位置。** 拖动途中、取消拖动、没有接收者时不下载、不生成整份暂存副本；否则一次误拖就可能悄悄下载整个远端目录。这是旧版已经修过的问题。
- 松开鼠标表示拖动手势结束，不表示文件已经交付。接收方可能稍后才要求内容；已经接受的交付任务必须继续存在，不能随手势结束或面板收起丢失。
- 下载显示为普通可取消传输。写入成功后才向接收方报告成功；失败或取消同时告诉用户和接收方，不能让 Finder 一直等待，也不能把半成品当成可用文件。具体取消清理见 ssh.md §9.1。
- 每次交付只报告一次结果。**新版改为：任务锁定原远端会话和条目，直至交付结束**；开始另一场拖动或切换标签不能把尚未完成的承诺指到新条目，也不能使它失去接收请求的能力，因为接收者可能在下一次拖动开始后才索要内容。
- 旧版 macOS 拒绝把远端 file promise 放回本应用，包括终端和 Filer，显示禁止落下的光标，不会为内部落点先做一次下载。
- 上述时序来自 Apple“通过文件承诺支持拖放”和“提供文件拖放数据”的约定，见 §12；它不意味着任意只接受文本的应用都接受远端文件承诺。

### 7.4 Windows／Linux 远端条目拖出

- 旧版先下载到本机临时副本，再把现成文件交给系统；“准备拖出”期间显示进度。用户需要保持按住鼠标直到准备完成。
- 准备过程中提前松手或取消，立即取消准备下载；不能在手势结束后继续把整个文件或目录下载完。取消清理见 ssh.md §9.1。
- 如果副本刚好在松手后完成，应提示“准备完成但拖动已结束，请重新拖动”，不突然启动没有鼠标手势的系统拖放。
- 暂存副本按每次拖动隔离，同名条目不相互覆盖；旧版不在拖动刚结束时删掉成功暂存内容，而在下次启动清理，因为接收程序可能仍在读取它。
- 这是旧版采用的交付方式，**不代表 Windows 或 Linux 平台本身绝无延迟交付能力**。本规格不强制新实现沿用旧技术；若采用其他方式，必须保留可见进度、可取消和交付成功／失败反馈。

### 7.5 拖到终端与拖回本应用

- 外部文件、本地 Filer 条目或已经实体化的本地副本落到终端时，向松手所在的终端插入路径，激活并聚焦该终端；不自动执行、不自动上传。多个路径以空格分隔，转义和 AI CLI 行为见 terminal.md §8。
- 目录拖到终端也只插入目录路径，不递归展开目录内容。落点是 SSH 终端时，插入的仍是本地路径，不能伪装成已经位于远端的文件。
- 隐藏标签、另一个分屏、文件面板和弹出对话框不得同时接收这次终端路径插入；文件传输占用输入时按 terminal.md §1 处理。
- 自己拖出的文件又回到原 Filer 时不回传一遍。识别到这次自拖回流时忽略，**但不能依靠一直不清除的“曾经拖过”状态拦住所有后续外部上传**。
- 手势被取消、松手未被收到或系统未报告结束后，下一次按下仍能开始新的拖放。拒绝落点后也必须撤去高亮。
- **[待定 D7]** 是否新增“远端条目直接拖到同一 SSH 终端以插入远端路径”，或跨会话的内部拖放传输。旧版 macOS 的 file promise 明确不提供这些能力；在决定前保持拒绝，不用一次隐含下载假装实现远端路径插入。

## 8. 本地文件浏览的差异

- 本地浏览、创建、删除及双栏重命名直接作用于本机；普通文件的“打开／打开方式”直接打开原文件，保存时没有远端回传过程。
- 旧版没有“在 Finder 中显示”入口；本地文件能拖到 Finder，不等于已经有“选中并揭示该文件”的菜单动作。
- 本地辅助 Filer 接收拖入时做复制而非移动：目录合并，普通同名文件的旧行为见 §6.3。复制大文件不能把整份内容放入内存；进度按文件完成情况推进，旧版没有本地复制的取消入口。
- 源文件已经位于目标目录时跳过并提示“已经在此目录”，不能把文件复制到自己而截断源内容。只有部分源项被跳过时说明跳过数量，其他项继续处理。
- 目录不能复制到自己或自己的后代目录，否则复制过程中会不断发现新生成的副本。链接到目录的递归处理和目标落点安全应与 ssh.md §9 的约定一致；本地复制不应通过接收侧链接写到目录外。
- 旧版复制普通文件时保留其权限位；不承诺完整复制属主、扩展属性、资源叉或时间戳。不得把它称为完整备份功能。
- Windows“此电脑”列出可用盘符，显示卷名称或通用磁盘名称和盘符；双击进入盘符。虚拟根不是实际目录，禁止在此新建、删除、复制落入或复制虚构路径；可移除介质不可用时正常显示读取错误，不反复弹“请插入磁盘”。
- 本地双栏仍只提供进入目录、新建目录、重命名和删除，以及向另一栏传输。辅助 Filer 才有默认应用打开、打开方式和外部拖放，不能混淆两者的旧版能力。

## 9. 用本地应用编辑远端文件

### 9.1 打开流程

1. 用户双击远端普通文件，或使用“打开／打开方式”。这只在辅助 Filer 中提供；目录的打开仍是进入目录。
2. 先把远端内容完整下载到系统临时区域中、仅供该远端条目使用的位置，保留原名称以方便编辑器识别文件类别。不同会话、不同远端路径下的同名文件互不覆盖。
3. 下载过程显示进度并可取消。失败、取消时不启动编辑器，也不监测未完成的副本。
4. 成功下载后开始监测本地副本的保存，再交给所选应用；刚下载完成本身不算用户保存，不能立即原样传回一次。
5. 默认“打开”使用系统为该文件关联的应用，并非固定的文本编辑器。选择“打开方式”时，macOS 选择已安装应用，Windows 使用系统打开方式选择器，Linux 允许选择本地程序。macOS／Linux 先选应用，取消选择不下载；Windows 先准备本地副本再展示系统选择器，取消时不打开应用，但已下载副本仍按正常的会话清理流程处理。无法启动时显示原因。
6. 手工选择成功使用的应用记为最近使用，最多保留六个，最近的排最前，重复选择移到前面；“其他应用”入口始终可用。应用列表与连接无关，不能混入服务器上的可执行程序。

旧版 macOS 默认从应用程序目录选择，Linux 默认从系统程序目录选择；这是选择器的初始位置，不是只能使用这些目录中的应用。Windows 使用系统选择器的历史由系统决定，不能承诺它也进入相同的六项菜单。

### 9.2 检测保存与自动回传

- 应用每次保存后，自动把本地副本内容回传到最初的远端完整路径，使用原活动会话；切换标签不改变目的地。
- 同一次保存可能连续改写、替换、改名。等待保存动作安静约 300 毫秒后再回传，避免把中间的空文件或半份内容上传。
- **必须支持编辑器先写新文件再替换原文件的保存方式，因为只认第一次打开的文件会在第一次保存后失去后续变化。** 编辑器备份、交换文件或单纯属性通知不能各自触发一次上传。
- 旧版以本地修改时间和大小区分有效变化；未做内容哈希比较。不能声称它能检测所有“大小与修改时间都不变”的改写。
- 显示“正在同步／已同步／同步失败”，错误包含原会话、文件名称和原因。旧版同步没有字节级进度和取消按钮，底部速率不代表真实回传速度；新版不能把未知量伪装成测速结果。
- 上传期间再次保存，完成本轮后仍处理后续保存，不能用旧一轮的“已同步”把后来的修改清掉。
- 回传成功后，刷新该条目所在目录的属性，但不强行把用户正在浏览的别的目录切回来。**这是新版新增**，理由是编辑器保存后面板的大小与修改时间也需要反映最新状态。
- 回传只负责文件内容，不把临时副本的权限、属主或本地编辑器偏好同步到服务器。

### 9.3 断线、失败重试与关闭

- 暂时断线时保留待回传内容。旧版会在失败后约 6 秒开始第一次重试，之后约 12、24、48 秒，最长等待约 60 秒；新的保存可提前唤起再次尝试，成功后恢复正常状态。
- 连续相同错误不反复弹出，用户仍能看到待同步／失败。重试期间终端及其他会话可继续操作。
- 普通断线不等于永久关闭编辑；原标签重新连接后，继续尝试上传尚未发送的保存。不能把另一台主机的新连接当成原编辑目的地。
- 永久关闭标签或退出应用时结束相关监测；所有保存都已成功回传的临时副本可以清理。**有未回传修改时必须保留本地副本，提示“修改未到达服务器”及可找到副本的位置**，否则关掉会话就会丢掉用户在外部编辑器里的工作。
- 下次启动清理上次遗留的已同步临时副本，保留标为未同步的副本。保留副本不是自动恢复编辑关系；旧版没有重新连接这些遗留副本的恢复列表。
- 接收文件的应用可能继续开着文档，旧版不感知用户何时关闭该文档；不能把“编辑器窗口关闭”作为已同步或清理的可靠条件。

### 9.4 重新打开、远端冲突与文件限制

- 旧版重新打开同一远端文件时复用原本地位置，但会先停止旧监测，再重新下载并重新开始监测。停止下载过程中的回传是必要的，否则半份下载会被当成一次保存上传。
- **新版改为：已有未同步本地修改时，重新打开不能直接以远端下载覆盖该副本。** 至少保留现有内容并说明有待回传修改；“重新下载”必须成为用户明确选择，不能因双击自动丢掉修改。
- 旧版没有远端版本比较，没有“别人已经修改”的冲突提示、自动合并、冲突副本或锁定远端文件；保存和重试都可能覆盖其他人的远端内容。
- **[待定 D5]** 新版远程编辑冲突策略：是否比较打开时版本与保存前的远端版本；冲突时是否暂停自动回传，并让用户选择覆盖、重新下载或另存副本；同样要决定离线后重连是否要求再次确认。理由是重试可能发生在别人已修改之后。决定前必须清楚说明旧版自动覆盖的边界，不能宣传已有并发编辑保护。
- 旧版没有远端文件大小上限、二进制识别限制或编码选择；系统默认应用可能是查看器，打开不表示一定能编辑。下载与回传按原始内容处理，不套用 SSH 终端字符编码，也不主动改变换行或文字编码。
- **[待定 D6]** 是否为远程编辑设置大文件阈值、二进制打开提醒、只读预览或同步中断时的专门恢复入口。它们属于新版产品选择，不能沿用终端编码设置替代文件编辑规则；决定前普通传输仍按 ssh.md §9 使用有界内存。

## 10. Git 改动面板

### 10.1 入口与适用范围

- 标题栏的“改动”按钮显示或收起 Git 面板；有仓库摘要时，按钮同时显示总新增和总删除行数。面板有关闭和刷新按钮，没有专用默认快捷键。
- 只对已连接的本地 shell 提供 Git 数据。依据的是该 shell 当前工作目录，**不是用户在 Filer 中另外浏览到的目录**；SSH 和纯 SFTP 不执行远端 Git 查询。
- 无仓库、SSH、纯 SFTP、无活动标签或本地会话已经结束时，面板仍可打开，显示“无法检测此目录的改动；仅适用于 Git 仓库”的可关闭空状态，不沿用上一标签的仓库。
- 旧版 Git 是独立的右侧面板，可以与当时放在左边的 Filer 同时打开；初始宽度 420 个逻辑像素，可调整到 280–760，旧版重启不记忆该宽度。
- **D8 已决定（2026-11-14）**：沿用旧版布局——Filer 在终端左侧、Git 面板在终端右侧，两者可同时打开，各自独立调整宽度；窗口不足以容纳时优先保证终端仍可操作。

### 10.2 仓库识别与展示

- shell 位于仓库子目录时识别整个工作区的仓库根；支持普通仓库、Git worktree 和子模块。分支名称保留完整层级；游离状态显示当前提交号前七位；还没有首个提交也能展示未提交内容。
- 顶部显示仓库名称、分支／游离提交标识、总增删行数；悬停能知道仓库完整位置。仓库干净时显示“工作区干净”，不能当作不在仓库。
- 改动列表包含已暂存、未暂存、未跟踪的文件；不显示被 Git 忽略的未跟踪内容。一个路径显示一行，按完整仓库相对路径字典序排列，带文件类别图标；重命名额外显示原路径。
- 状态标记为：M 修改、A 新增、D 删除、R 重命名、C 复制、U 未跟踪、! 冲突、T 类型变化。冲突优先于一般修改；这些是界面标记，不要求与 Git 两列状态原文一致。
- 每个文件显示新增和删除行数，无法计算的显示破折号；顶部累计只使用已知行数，不能把二进制变化错误地说成新增或删除零行。
- 已有提交的文件，其行数表示相对当前提交的净内容变化；暂存与未暂存修改可能互相抵消，此时仍可列为改动但显示零净增删。旧版不分成“暂存区／工作区”两个列表。
- 未跟踪文本和无首个提交时的文本，内容可全部视为新增。旧版只有普通文件、大小不超过 512 KiB 且不含零字节时才为这类文件计算行数；其他情况不给伪造的统计。
- 文件名里的空格、制表符、换行、中文、方括号等必须完整保留，不能按显示文本拆成多项，也不能被解释为路径匹配表达式。Git 一手约定见 §12 的 git status、git diff 文档。

### 10.3 diff

- 初始只取文件列表和统计；用户展开某一项才读取该文件的差异，可同时展开多项，再点收起。
- 已跟踪文件对比当前提交与工作区，包含净变化；重命名差异必须同时考虑原路径与现路径，避免把纯改名画成整份新增。
- 展示单列行内差异，新增和删除使用不同颜色及正负标记，保留上下文，每段通常显示三行上下文。新增与上下文使用新版本行号，删除使用旧版本行号；不把 Git 元数据标题当作文件正文。
- 没有净内容变化时说明“相对当前提交没有净内容变化”；条目已经不再有改动时说明其已不可用；读取失败就地显示原因，不使整个面板消失。
- **新版改为：二进制文件、仅元数据变化或无法提供文本差异时给出明确说明**，不能只剩一个空白展开区。旧版对部分二进制差异过滤后会看起来什么也没显示。
- 差异内容最多读取约 512 KiB，界面最多展示 3000 行；超过任意限制显示“差异已截断”。不能先读完无限大的差异，再靠界面截断节约内存。
- 每次取得新摘要，已经展开的文件也重新读取，即使文件行数没变。**必须做到这一点，因为替换等长内容后净增删数字可能相同，不能因此继续展示上一次正文。**

### 10.4 刷新和性能

- 新本地会话连接成功、识别到本地命令结束、用户点击刷新，以及 Git 提交／丢弃操作完成后更新摘要；旧版没有持续后台轮询和覆盖所有外部文件修改的实时监听。
- shell 离开仓库、切到另一个仓库或会话关闭时，清除之前的摘要。过时请求不能在较新请求之后恢复旧仓库或旧文件数。
- 仓库检查失败不阻塞终端；显示错误原因。**新版改为：区分“不在仓库”和“读取失败／Git 不可用”**，否则用户无法判断是目录不对还是命令环境有问题。
- 摘要读取不应获取不必要的写锁，不执行用户配置的外部差异查看器或内容转换程序；展开差异也应遵守同一约束，因为刷新只是查看，不应启动另一个应用或运行任意转换。
- 同一会话的重复刷新合并或以最新一次为准，差异按需读取，不对每个文件预读全文。关闭 Git 面板不能打断终端命令。
- Git 分支在终端标签／提示符中的显示规则见 ui-shell.md §2 和 local-shell.md §5；面板读取完整改动摘要不意味着每画一次提示符就启动 Git 进程。

### 10.5 旧版另外具备的写操作

虽然入口叫“改动面板”，旧版已经可以提交和丢弃，不能把它提炼成纯只读功能：

- 有改动时显示提交说明输入框、“提交”按钮和更多菜单。说明去掉首尾空白后不能为空，旧版接受的说明不超过 16 KiB；输入框 Enter 可提交。
- “提交”表示暂存仓库内全部当前变化，再创建一次提交，包括修改、删除和未被忽略的新内容；不只是当前展开的文件，不推送远端，也不提供逐文件暂存。Git 行为见 §12 的 git add、git commit。
- 提交成功清空说明并刷新摘要；失败保留说明、展示错误，可关闭错误提示后继续操作。**新版新增：明确说明失败可能已经留下暂存内容**，因为暂存成功后，身份配置、钩子或签名失败都可能使提交未完成，不能提示成全部回滚。
- 每项有“丢弃该文件改动”。确认框显示相对路径：已跟踪内容说明暂存和未暂存编辑都会丢失；新增、未跟踪或复制出的内容说明会永久删除。取消不改动。
- 丢弃已跟踪内容恢复当前提交中的内容及暂存状态；丢弃新增项移除新内容；丢弃重命名恢复原路径、移除新路径，不触及无关文件。
- 更多菜单里有“丢弃全部改动”，需要单独确认仓库名称，并说明暂存、未暂存、未跟踪改动都会永久丢失；Git 忽略的内容不在清理范围内。没有首个提交时也能清理新增和已暂存内容。
- Git 丢弃没有应用内撤销、废纸篓或自动备份；其破坏范围不同于 §5.4 的普通目录删除，应明确写出。
- 写操作进行时禁用刷新、另一个写操作和会改变操作对象的列表操作。完成后移除不存在的展开项；失败显示具体 Git 错误，不报成功，也不静默重试写操作。

## 11. [MAS] 沙盒发行版

- 上传来源和下载目标的授权规则见 ssh.md §9.4。本地浏览也不能因为文本路径可见就视为已获授权；没有权限时提供系统文件／目录选择入口，并解释需要访问哪一处。
- 用户选择本地目录后，该目录内的浏览、创建、编辑和复制应在已授权范围内工作；恢复上次浏览位置时同时恢复其授权，授权失效则重新选择，不反复显示空目录。
- Finder 拖入提供的是这次用户操作选定的来源；复制到另一个目录仍需要目标访问权限。Finder 接受远端拖出时使用 file promise，落点处理见 ssh.md §9.4 与 §7.3。
- **[MAS][待定 D9]** 外部编辑器打开临时副本、编辑器原子替换后继续同步、最近应用的再次启动，以及调用本地 Git 的可行方案，需要在正式沙盒发行版中验证。不能把 Direct 版可访问任意临时路径、应用或系统 Git 的能力直接写成商店版承诺。
- 若商店版最终不能支持某项，明确禁用相应入口并说明范围；不要让用户完成下载和编辑后才发现保存不能回传。这里只规定用户可见结果，不指定授权和进程组织方式。
- 文件访问与跨启动持续授权的一手依据为 Apple“配置 macOS App Sandbox”和“从 macOS App Sandbox 访问文件”主题，后者包含“持久访问用户选择的文件”章节，见 §12。系统隐私授权和应用沙盒授权不能相互替代。

## 12. 外部系统的一手依据

以下资料只解释外部约定；本规格中的宽度、按钮、时间阈值、排序和状态文案是产品行为，不是平台强制要求。

- Apple：[Supporting Drag and Drop Through File Promises](https://developer.apple.com/documentation/appkit/supporting-drag-and-drop-through-file-promises)。说明拖动未实体化文件、由接收方确定落点，以及成功／失败完成交付的时序；对应 §7.3。文档中给出的示例程序和内部名称不属于本规格。
- Apple：[Providing Data for a Drag](https://developer.apple.com/documentation/appkit/providing-data-for-a-drag)。说明文件与普通文字是不同的拖放数据，以及承诺文件的提供时机；对应 §7.2、§7.3。
- Apple：[Configuring the macOS App Sandbox](https://developer.apple.com/documentation/xcode/configuring-the-macos-app-sandbox)、[Accessing files from the macOS App Sandbox](https://developer.apple.com/documentation/security/accessing-files-from-the-macos-app-sandbox)。用户选择文件的访问范围、“标准用户交互访问文件”和“跨启动持续访问”主题对应 §11；旧版未经沙盒验证的能力不能据此自动认定可用。
- IETF：[SSH File Transfer Protocol，草案第 2 版](https://www.ietf.org/archive/id/draft-ietf-secsh-filexfer-02.txt)，这是 SFTP 第 3 版的协议草案，**不是一份已发布 RFC**。其文件名称、文件属性、读取目录、移除与重命名、链接相关章节对应 §3–§6。SFTP 与经常被称为安全文件传输的其他协议不应混用；共用传输约定仍以 ssh.md §8、§9 为准。
- Git：[git status](https://git-scm.com/docs/git-status)。稳定的状态格式、暂存与工作区状态、重命名前后路径，以及可保留特殊字符的路径输出方式，对应 §10.2。
- Git：[git diff](https://git-scm.com/docs/git-diff)。相对当前提交的比较、增删行统计、二进制统计、重命名、上下文和禁用外部差异处理的选项，对应 §10.2–§10.4。
- Git：[git rev-parse](https://git-scm.com/docs/git-rev-parse) 和 [gitrepository-layout](https://git-scm.com/docs/gitrepository-layout)。工作区根目录、Git worktree 与子模块的元数据间接位置，对应 §10.2；不把某一种元数据存放形式当作唯一仓库识别条件。
- Git：[git add](https://git-scm.com/docs/git-add)、[git commit](https://git-scm.com/docs/git-commit)、[git restore](https://git-scm.com/docs/git-restore)、[git reset](https://git-scm.com/docs/git-reset)、[git clean](https://git-scm.com/docs/git-clean)。全部暂存、提交失败、恢复两处状态、清理未跟踪内容及保留忽略内容的语义，对应 §10.5。列出命令主题用于核对外部行为，不规定新版必须用某一条命令实现。

## 13. 验收用例（实现时转成自动化测试）

以下用例除明确指向待定项的部分外，均是新版应满足的结果。涉及操作系统文件拖放、外部编辑器和系统授权的用例，应在对应平台的真实桌面环境执行，不能只靠模拟输入判定通过。

### 13.1 面板与定位

- 在本地与两个 SSH 标签中分别浏览不同目录，切换标签并切换分屏后，各自恢复本会话最后成功目录，来源标识正确；把其中一个标签移到另一分屏，目录和正在进行的传输不重建。
- 调整 Filer 宽度并收起，重启应用后宽度和显隐恢复；展开位置在标签栏与终端之间，最窄可操作宽度和窗口约束正确。
- 打开纯 SFTP 标签后主区显示远端／本地双栏，状态栏说明浏览器已经打开，⌘⌥→ 不重复展开辅助栏；切回 SSH 后正常恢复辅助栏状态。
- Filer 隐藏时按 ⌘J，直接出现当前 shell 目录，不短暂跳回家目录；面板已开时按同一个键也重新读取目标目录。
- 通过终端右键、面板定位按钮和 ⌘J 定位同一 shell，得到相同目录；shell 后来切目录不会自动带走 Filer。
- 目录查询失败时状态栏显示原因，原浏览目录不被家目录冒充；查询成功但读取目录失败时，路径和保留的旧列表不会错误配对。
- 发起定位后迅速切换标签或关闭原标签，迟到的结果不会改变另一个标签的面板；本地 shell 收到其他主机的目录上报时，不将其误当成本机路径。
- SSH 断开时仍显示远端身份和断线提示，不能自动改为本地列表；重连后可刷新或回到远端家目录。

### 13.2 浏览与文件操作

- 路径栏 Enter 导航、Esc 恢复；家目录入口、上一级、刷新有效；相对路径按当前浏览目录解释；根目录不会走到空路径。
- Windows 盘符根目录的上一级显示“此电脑”，可以打开盘符，不能在虚拟根新建、删除、接收复制或复制出不存在的目录路径。
- 列表目录在前、名称忽略大小写按字典序排列，数字名称不会无声明地变成自然排序；隐藏项默认可见，未知属性不会显示为确定的零大小。
- 大目录未读完时首批条目已经可见且显示仍在加载；继续滚动、主题切换和同类图标加载不使界面明显停顿；分批插入不改变用户实际选中的对象。
- 迅速连续进入两个目录，让第一个请求后返回，最终仍显示第二个目录；失败的旧请求不能清除第二个目录的加载状态或内容。
- 权限不足、目录不存在和路径为普通文件分别显示错误；macOS 接受访问授权后可成功刷新，无需重启；已有名称但属性读不到时仍展示该名称。
- 打开链接到目录、链接到文件、悬空链接分别进入、打开或报错；删除链接只删链接，目标保持原样。
- 单击、右键和双击符合单选规则；辅助 Filer 与纯 SFTP 双栏只展示各自已定义的菜单和按钮，不借用终端全选声称文件多选。
- 新建文件和目录的 Enter、失焦、Esc 分别提交或取消；空名称、带目录分隔符、已有同名项被正确处理；名称检查后发生同名竞争，也不会清空对方文件。
- 双栏重命名预填旧名称，取消及名称不变不操作，输入越出当前目录的名称被拒绝，成功只刷新对应一栏。
- 删除确认正确显示文件／空目录／链接类型、来源、名称、路径和不可撤销说明；Esc 或取消不删除，Enter 只执行一次；非空目录不会递归删除，普通删除不进入废纸篓。
- 复制完整路径、名称、当前目录路径保持原字符；剪贴板写入失败可见。

### 13.3 传输与拖放

- 从上传菜单分别选择多个文件和多个目录，按顺序上传到请求发起时的远端目录；中途切换目录或标签不改变已开始任务的目的地。
- 普通下载可在保存选择器更名，目录下载落在所选父目录下面并保留目录名称；取消选择器无传输副作用；双栏的接收目标是另一栏当前目录。
- 双栏遇到同名文件时确认替换，同名目录时确认合并，文件与目录类型冲突时报错，下载不覆盖本地链接；对尚未决定的统一冲突选择不虚构入口。
- 底部能区分处理中、上传、下载、复制、准备拖出、同步、完成、取消和失败；总量未知显示不确定进度，错误详情不随短时进度提示一起消失。
- 一批第二项失败或取消后，第一项保留，其余不再开始；传输中另一批被明确拒绝；取消后的清理和终端可交互性另按 ssh.md §12 及 §9 验收。
- 一次目录传输的路径越界、链接、特殊文件、取消清理及流水线性能用例复用 ssh.md §9、§12；从菜单、拖入或 file promise 触发时都不能绕过这些条件。
- 从 Finder 拖文件和目录到远端辅助面板的工具条、路径区、列表空白或底部，均高亮并上传到显示目录；放到目录行也不未经说明改变目标。
- 在双倍缩放显示器上拖入，松手位置命中正确面板；拖到另一终端分屏、覆盖对话框或隐藏标签不会同时上传并插入路径。
- 拖到本地辅助 Filer 执行复制，源项保留；拖回本来所在目录时跳过并解释；把目录拖到它自己的后代目录时拒绝，不生成无限副本。
- 轻点文件行不启动拖出，快速拖离行范围仍能启动；被取消或丢失松手后，下一次拖放仍可正常使用。
- macOS 拖出远端文件或目录时，接收者接受之前没有下载；取消或放回本应用不产生下载；Finder 接受后写入其指定位置，交付完成只报告一次。
- Finder 已接受而下载失败或用户取消时，Finder 和面板都收到失败／取消结果；松手后才提出的交付请求不被丢失。
- Windows／Linux 准备远端拖出时显示进度，提前松手立即停止；成功暂存内容在接收者仍读取时可用，下次启动清理。
- 本地文件和目录拖到终端时，只向松手所在终端插入正确转义的路径、获得焦点，不执行命令；远端 macOS 条目内部落点仍按已定义规则拒绝。
- 同一文件从本应用拖出又拖回时，不自动上传回源目录；结束后再次从 Finder 拖入其他文件不会被残留状态拦截。

### 13.4 远程编辑

- 两个远端目录和两个活动会话里有同名文件时，打开后的本地副本互不覆盖；下载未完成或取消时不启动编辑器，也不上传半成品。
- 默认打开使用系统关联应用；macOS／Linux 选择其他应用成功后按最近顺序最多保留六项，取消选择不下载；Windows 取消打开方式选择时不启动编辑器，已形成副本正常清理；本地文件直接打开原件，不进入远端回传流程。
- 编辑器连续保存和“新文件替换原文件”式保存均能持续回传；一次保存的多个动作不会造成多次空文件上传，备份文件变化不误触发同步。
- 上传进行时再次保存，最终远端包含最新一轮保存，面板不能提前把后续变化标为已同步；成功刷新属性不把 Filer 导航到另一个目录。
- 暂时断线后保存，失败可见且保留副本，按照重试间隔再次尝试；原会话重连后能回传；连续相同错误不会反复刷屏。
- 永久关闭标签或退出时，已同步副本可以清理，未同步副本被保留并告知位置；下次启动仍不删除未同步副本。
- 有未同步本地编辑时再次打开相同远端文件，不直接下载覆盖编辑内容；不同编码和换行内容下载后未编辑即关闭，原始内容不被终端编码转换。

### 13.5 Git 与沙盒

- 从仓库深层目录、worktree、子模块、无首个提交及游离提交状态打开 Git 面板，仓库与分支身份正确；离开仓库或切到 SSH 后不显示旧摘要。
- 暂存、未暂存、未跟踪、重命名、复制、冲突和类型变化按对应状态显示；特殊字符路径保持完整；忽略内容不显示；仓库干净与读取失败可区分。
- 未展开任何文件时不读取文件正文差异；展开后显示正确增删、上下文和行号；等长修改后刷新仍更新正文；二进制有明确提示，超过 512 KiB 或 3000 行显示截断。
- 净变化为零但状态仍有变化时保留条目并说明无净内容变化；另一程序已经清理的条目展开后提示已不可用。
- 本地命令结束和手动刷新更新摘要；让旧请求延迟返回，最终结果仍属于最新目录与当前会话，终端不被刷新拖住。
- 输入空白提交说明时不能提交；有效说明提交全部改动而不推送；成功清空说明，失败保留说明和具体错误，并如实保留已经完成的暂存结果。
- 丢弃单文件或全部改动前取消确认，仓库内容不变；确认后分别恢复已跟踪内容、移除新增项、撤销重命名，全部清理仍保留 Git 忽略内容。
- [MAS] 未授权目录可选择授权后浏览；恢复目录时授权失效会请求重新选择；上传和下载遵循已授权来源与目标；不能用路径文字代替授权。
- D1–D9 决定后分别补充跨重启目录恢复、浏览增强、多选与重命名、统一冲突、远程编辑冲突、文件限制、远端内部拖放、右侧空间分配和沙盒编辑／Git 用例。决定前不得把候选能力的测试列为已通过。

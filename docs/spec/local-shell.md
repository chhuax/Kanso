# 本地 shell 规格

覆盖本地终端会话：启动哪个程序、以什么方式启动、环境变量、locale、zsh 提示符集成、工作目录查询、会话结束。终端显示行为见 `terminal.md`。

## 1. 启动命令

- 配置里的 Shell 字段填的是**一条命令行**，不只是程序名。例如 `wsl.exe -d Ubuntu`、`pwsh -NoLogo`。按 shell 的规则拆分参数（Windows 按 Windows 命令行的规则拆分）。
- 字段为空时使用默认 shell：
  - Unix 取 `$SHELL`，没有就用 `/bin/bash`；
  - Windows 取 `COMSPEC`，没有就用 `powershell.exe`。
- 起始目录：优先用配置里填的目录，否则用用户主目录。
- 初始终端尺寸 80×24，之后跟随界面实际大小调整。

## 2. macOS 上以 login shell 启动

- **原因**：从 Dock 或 Finder 启动的应用，继承的是 launchd 的环境，PATH 里只有四个系统目录：没有 Homebrew、没有 `/usr/local/bin`，`/etc/paths.d` 和 `~/.zprofile` 添加的路径也都没有，因为 `/etc/zprofile` 和 `~/.zprofile` 只在 login shell 下执行。如果用户的 `.zshrc` 里用到了 `brew` 或它安装的工具，就会一行接一行地报错。Terminal.app、iTerm2、VS Code 都是用 login shell 启动的。
- **规则**：
  - 只在 macOS 上加 `-l`。
  - 只在命令行**只有一个程序名、没有任何参数**时才加。命令行带参数时，完全按用户写的执行；用户可以写 `zsh +l` 明确不要 login shell。
  - 只给已知的 shell 加：bash、csh、dash、fish、ksh、nu、pwsh、sh、tcsh、xonsh、zsh，匹配时取路径的最后一段。不认识的程序不猜测。
- Linux 上的终端习惯启动非 login shell，而且桌面会话本身已经带有用户的环境，所以不加。

## 3. 环境变量

- `TERM=xterm-256color`、`COLORTERM=truecolor`、`TERM_PROGRAM=Kanso`、`TERM_PROGRAM_VERSION=<版本号>`。
- **删除 `NO_COLOR`**：Kanso 明确提供彩色终端，不能把启动 Kanso 的进程（构建工具、代理进程等）带来的"禁用颜色"约束传给用户的 shell。同类的变量也要检查一遍，比如 `CLICOLOR=0`、`FORCE_COLOR=0`。
- 新版的环境变量清单**要明确列出**：哪些继承自父进程、哪些删除、哪些覆盖。不要零散地处理。

## 4. Locale

**问题**：macOS 上 GUI 应用的环境里没有设置任何 locale，shell 就会运行在 C locale 下，`ls` 会把中文文件名显示成 `???`。

**决策顺序**：
1. 配置里**明确填写了 locale**，并且格式合规（只含字母、数字和 `_ - . @`，长度不超过 64）：直接作为 `LANG` 使用。
2. 会话编码**不是 UTF-8**（例如 GBK）：不自动设置，因为只有用户自己知道该用哪个 GBK locale。
3. 当前环境里已经有 `LC_ALL`、`LC_CTYPE`、`LANG` 中的任意一个（值不为空）：不动。
4. 以上都不满足时，自动选一个 UTF-8 locale：
   - **macOS**：根据用户系统的语言和地区推算候选，依次检查系统是否带有这个 locale（`/usr/share/locale/<名称>` 目录存在），取第一个存在的；都没有就用 `en_US.UTF-8`，系统一定带有它。
     - 候选顺序：先"语言 + 用户所在地区"，再"语言 + 该语言的常用地区"。例如系统设为"英文、地区中国"时，系统里没有 `en_CN`，就退回 `en_US`。
     - 常用地区：en→US、zh→CN、ja→JP、ko→KR、de→DE、fr→FR、es→ES、it→IT、pt→BR、ru→RU、nl→NL、sv→SE、pl→PL、tr→TR。
     - 系统语言标识里的书写体系部分要去掉，例如 `zh-Hans` 变成 `zh`；`@` 后面的修饰部分也要去掉。
   - **Linux / BSD**：用 `C.UTF-8`。glibc 2.35 起内置了它，主流发行版很早以前就自带，比任何具体语言的 locale 都可靠。
   - **Windows**：不设置。Windows 的 shell 从控制台获取代码页，MSYS2 和 Cygwin 的工具在没有 locale 时默认就是 UTF-8。

## 5. zsh 提示符集成

**目标**：本地 zsh 提示符使用两行布局，第一行显示上下文标签，第二行保留用户提示符正文；输出 OSC 133 标记，用于命令分隔线和命令跟踪（见 `terminal.md` §4、§5）。**不修改用户的任何文件。**

### 5.1 加载方式
- 在应用自己的数据目录下生成一组 shim 文件，启动 zsh 时把 `ZDOTDIR` 指向这里，同时用另一个环境变量告诉 shim 用户原来的配置在哪里。用户自己设置了 `ZDOTDIR` 就用它，否则用主目录。
- zsh 的**每一个**启动文件（`.zshenv`、`.zprofile`、`.zshrc`、`.zlogin`、`.zlogout`）都要有对应的 shim。shim 只做一件事：加载用户自己的同名文件，保证任何一个文件都不会被跳过。
- `.zshrc` 的 shim 还要额外做两件事：
  - 把 history 文件的位置改回用户原来的位置，否则 zsh 会把历史写进 shim 目录；
  - 最后注册我们的 precmd hook。
- 文件内容没变时不重写，避免无谓地改动修改时间。
- shim 写入失败时，shell 完全按原样启动，只是没有这一行提示。
- 删除 shim 目录就能彻底移除这个功能，不留任何痕迹。
- 不是 zsh 的 shell 会忽略这个变量，不受影响。bash、fish 的集成 **不在首版范围内**；fish 默认就会发送 OSC 7。
- 新版增加一个设置项，可以关闭提示符集成。

### 5.2 提示符内容
- **两行布局**：第一行按 Node、目录、Git 分支的顺序显示标签，每个标签为图标加文字，标签之间留两个空格；第二行显示原提示符的正文（core），不再插入目录或分支，第一个 `%#` 保持红色，末尾保留用户输入间距。
- **标签外观**：小圆角（约 3 逻辑像素，不是胶囊形）、贴近终端背景的底色，深浅主题分别取 `terminal.chipBackground` / `terminal.chipBorder`（内置图标色见下文 `terminal.chipIcon`）。左右不外扩，上下在行内收紧；在文字背景之上、文字之下绘制。只有最新且尚未执行命令的提示符画这套标签。提交命令时，zsh shim 通过 `zle-line-finish` 把标签行重绘为顶格紧凑的纯文本（格式为 `目录`、有仓库时接 `git:(分支)`、有 Node 时接 `node:版本`，不含标签框、图标与内边距空格），随后立即恢复 `PS1`。已经执行过的提示符行（命令和输出除外）不再画标签，也不画私有区图标，保持原字号，统一使用次要文字色 `terminal.gutterText`。
- **Node 标签**：只有当前目录或上级存在 `package.json` 且 PATH 中有 `node` 命令才显示。向上查到 Git 根目录或 `$HOME`（包含该目录）为止，最多到文件系统根目录；版本由 `node --version` 获取，当前目录和 PATH 不变时复用缓存。图标为 U+E718（Lucide hexagon），文字绿色。
- **目录标签**：U+F07B（Lucide folder）加目录，默认前景色。当前待输入的提示符为粗体；已经执行过的提示符去掉粗体。用 `~` 缩写主目录。超过 36 个字符时，只保留尾部若干个**完整的**路径段，前面加 `.../`。
  - 同一行连续 CHIP 单元格组成一个标签，首个非空格字符是 U+F07B 时识别为目录标签，首尾空格也可点击。仅本地集成 zsh 最新命令块的提示符标签响应；命令运行中、备用屏幕、鼠标上报、回滚旧提示符、拖动和多击均不响应。悬停可点击标签时显示手形光标；单击打开选择器且不选中命令块。
  - 选择器沿用浮动面板样式，锚定在标签下方，屏幕下方放不下时改在上方。搜索框占位为“搜索目录…”；首项始终是“.. (上级目录)”，之后按名称排列当前工作目录的子目录（含指向目录的符号链接），每项显示文件夹图标和名称。
  - 工作目录取终端已有的 shell cwd 查询（OSC 7 / 进程 cwd），不解析标签文字。目录读取和名称预处理在后台执行，列表滚动复用行视图；输入立即按现有的大小写不敏感模糊匹配过滤。默认隐藏点号开头的目录，仅查询以 `.` 开头时显示并参与匹配。
  - ↑ / ↓ 选择，回车或双击确认；Esc 或点外部取消并回到终端。确认通过私有序列 `ESC [ 9001 ~`、目标绝对路径的 UTF-8 字节十六进制编码、LF（0x0A）发送；编码不含空格，接受大小写十六进制。
  - shim 的 ZLE widget 解码后执行 `cd -- <路径>`，触发 chpwd 钩子，重新生成目录 / Node / Git 标签、上报 OSC 7 并 `zle reset-prompt`；保留已输入的整行和光标位置，不执行输入行、不写历史、不产生新命令块。空格、单双引号、中文及换行都按原路径传递；目录不存在时静默忽略，不重绘、不改输入或目录。
- **Git 分支**：
  - **直接读 `.git/HEAD` 文件，不启动 git 进程**，每显示一次提示符就启动一次进程太慢。
  - 从当前目录逐级向上找 `.git`：如果是目录，读其中的 `HEAD`；如果是文件（worktree 或 submodule），按里面的 `gitdir:` 找到真正的目录，相对路径以 `.git` 文件所在的目录为基准。
  - `HEAD` 内容是 `ref:` 时显示分支名（去掉 `refs/heads/` 前缀）；处于 detached HEAD 时，显示提交号的前 7 位；其他内容一律不显示。
  - 分支名是数据：要转义提示符里的 `%`。用户开启了 `promptsubst` 时，通过变量引用插入分支名，防止分支名里的命令替换被执行。
  - 标签中使用 U+E0A0（Lucide git-branch）加绿色分支名；无仓库时不显示。三个图标由渲染器内置绘制，均为单格宽、竖直居中；在标签内一律用次要文字色 `terminal.chipIcon`（取值同 `text.secondary`，与状态栏图标同一档灰，深浅主题各自取值），不参与最低对比度调整；标签外出现同码点时仍跟随前景色。标签文字不变（目录名默认前景色，仅当前待输入提示符为粗体；分支名、Node 版本绿色）。
  - 每个标签用 `ESC ] 777 ; kanso-chip ; start BEL` 和 `ESC ] 777 ; kanso-chip ; end BEL` 包住，PS1 中用 `%{…%}` 包为零宽。标签属性跟随单元格滚动、重排和回滚；缺少 end 时遇换行或 OSC 133 A 自动结束，未知 777 子命令忽略。
- **和用户原有提示符合并**：
  - 去掉原提示符里的目录转义（`%~`、`%d`、`%/`、`%c`、`%C`、`%.` 以及带数字的写法；后三个只显示目录尾部几段，oh-my-zsh 默认主题就用 `%c`），因为目录已经由我们统一显示在前面。
  - 原提示符里如果用了 `$PWD` 这类表达式，不去改写，继续作为第二行用户正文的一部分。
  - 去掉用户名和与它相连的主机名（`%n`、`%N`、`@%m`、`@%M`），因为标签上已经能看出是哪个会话。
  - 合并多余的空格，去掉开头的空格，保留末尾的空格（这是光标和提示符之间的间距）。
- **OSC 133 A 和命令块间距**：
  - 第一个提示符只输出 OSC 133 A，不插入空行，避免时间戳栏和缓冲区从第二行才开始。
  - 之后的每个提示符前输出 OSC 133 A 和**两个空行**，分隔线画在这两行正中间。
  - 这两种 OSC 133 A 要能区分开（例如带不同的参数），终端据此判断分隔线放在哪里。

### 5.3 新版需要补充的
- precmd 里还要输出 **OSC 7**（当前目录），以及 OSC 133 的 B、C、D 标记（D 带上退出码），让命令跟踪不再依赖猜测提示符（见 `terminal.md` §5.1）。
- 提示符的颜色要跟随浅色和深色主题（用 ANSI 调色板的索引，不写死具体颜色）。

## 6. 工作目录查询（本地）

启用 shell 集成时，Windows 的交互式 PowerShell（含 `pwsh`）在每次提示符处上报文件系统目录。默认提示符用终端调色板和箭头分隔目录、Git 和上一条命令的结果。目录段缩写主目录和长路径。

Git 段显示当前分支或游离提交的前七位，并用 `↑`、`↓`、`+`、`~`、`?`、`!` 分别标记领先、落后、暂存、未暂存、未跟踪及冲突项数，只显示非零项。状态使用一次只读的本地 Git 查询，Git 不可用时仍显示分支。自定义提示符保持原样。

Windows「设置 → 通用」的「彩色 PowerShell 提示符」默认开启。关闭后，新开的 PowerShell 会话使用普通提示符，仓库内仍显示纯文本分支，目录继续上报。

用户按 ⌘J 时：
1. 如果 shell 上报过 OSC 7 等目录信息，直接使用（见 `terminal.md` §12）。
2. 否则通过系统查询：
   - 用 PTY 主端的 `tcgetpgrp` 拿到**前台进程组**，读它的组长进程的工作目录（macOS 用 `proc_pidinfo`，Linux 读 `/proc/<pid>/cwd`）。这样嵌套 shell 或从 shell 启动的程序也能查对。
   - 组长进程可能已经退出（管道的第一段通常最先退出），这时退回到查 shell 进程本身。
- Windows 上没有对应的系统查询，只能依靠 OSC 上报。

## 7. 会话的生命周期

- 读取 PTY 输出的循环在专门的线程上进行，读到数据后交给终端处理。等待下一次读取之前，先把缓冲里的数据交出去，避免最后一点输出卡在缓冲区里不显示。
- **父进程里必须关闭 PTY 的从端**，否则 shell 退出后读循环永远等不到 EOF。
- 区分两种结束方式：用户主动关闭，不提示"会话已结束"；shell 自己退出，提示，并在有退出码时显示退出码。
- 关闭会话时先结束 shell 进程，再回收资源。

## 8. [MAS] 商店版

商店版的本地 shell 受沙盒限制，具体影响和待实测的项目见 `design.md` §5。本规格中的所有内容都按官网版（无沙盒）编写；商店版启动时再补充差异。

## 9. 验收用例

- 在 macOS 上从 Dock 启动应用，新开本地标签：PATH 里有 Homebrew，`.zshrc` 里用到 `brew` 的那几行不报错。
- Shell 字段填写 `zsh +l` 时，不会再加上 `-l`。
- Kanso 从带有 `NO_COLOR` 的环境中启动时，shell 里看不到 `NO_COLOR`。
- 中文系统下没有设置 locale 时，`ls` 能正确显示中文文件名。
- GBK 编码的会话不会被自动设置 UTF-8 locale。
- 提示符集成不修改用户的任何文件；history 仍写在原来的位置；删除 shim 目录后 shell 恢复原样。
- 在 git worktree、submodule、detached HEAD 下，分支显示正确；分支名里带 `%` 或 `$(...)` 时，不会被解释执行。
- 在嵌套 shell 里，或者 `sudo -s` 之后，⌘J 能定位到正确的目录。
- shell 自己退出时会提示退出码，用户主动关闭时不提示。

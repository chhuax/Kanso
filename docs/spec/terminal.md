# 终端规格

覆盖终端视图里与产品行为有关的部分：输出处理、时间戳/行号栏、清屏语义、命令分隔线、命令跟踪与标签活动、AI CLI 识别、语义着色、选区与剪贴板、按键、链接、搜索、工作目录上报、IME。
VT 序列本身的解析由终端引擎负责，按 xterm 的行为实现，本文不展开。补全的数据来源见 `completion.md`，本地 shell 的集成见 `local-shell.md`。

## 1. 输出处理顺序

会话的原始字节依次经过：
1. **文件传输哨兵**：XMODEM 由用户手动启动，运行期间独占整个字节流；否则由 ZMODEM 哨兵检测握手。哨兵**必须拿到原始字节**。
2. **编码转换**：会话编码不是 UTF-8 时，在这里解码。每次重新连接都要重置解码器，丢弃上一次会话残留的半个字符。
3. 交给终端引擎。

文件传输进行期间，键盘输入和粘贴**一律不发往会话**，否则会破坏正在传输的二进制帧。

## 2. 时间戳与行号栏

借鉴 WindTerm 的标志性功能：终端左侧有一列，显示每一行的产生时间和累计行号。

- **四种模式**：关闭 / 只显示行号 / 只显示时间 / 两者都显示。默认关闭（产品决定 2026-11-16）；第一次从状态栏打开时显示两者，在"会话"菜单里切换模式。
- **AI CLI 会话单独处理**：识别出 AI CLI（§6）后，这个标签的时间戳栏默认隐藏，因为全屏 TUI 不需要它。用户可以只给这个会话打开，不影响全局设置；同一个工具重复上报识别结果时，保留用户的选择；工具退出或换成另一个工具时，这个临时设置作废，回到全局设置。状态栏上的开关在 AI 会话里只作用于当前会话。
- **时间**：每一行在被写出时记录墙钟时间，显示格式为 `HH:MM:SS.mmm`，不随语言变化。
- **行号**：会话内累计计数。回滚缓冲满了以后开始丢弃最早的行，但**行号不能停止增长，也不能重新开始**。这是旧实现踩过的坑：缓冲区满后底部换行会复用顶部的行，如果不单独计量被丢弃的行数，行号就会停在缓冲区刚满的那一行。
- 光标所在行高亮显示。
- 屏幕上还没写过内容的空白行，不显示时间和行号。
- **全屏程序（alternate screen，例如 vim、top）期间**，这一列留空，时间和行号对全屏画面没有意义。
- 执行 `clear`（见 §3）之后，行号从 1 重新开始。
- 这一列**不参与文本选择和复制**。
- **性能要求**：每产生一行，维护时间和行号的开销必须是摊还 O(1)，不能随回滚长度增长（旧实现曾因为每行都从数组头部删除元素而变慢）。

## 3. 清屏语义

- **shell 执行 `clear`**：表现为同一批输出里 ED 2（清屏）和 ED 3（清回滚）成对出现。Linux 上是先 ED 2 后 ED 3，macOS 上是先 ED 3 后 ED 2。只有两者成对才视为 `clear`：清空回滚，行号从 1 重新开始。
- **只有 ED 2、没有 ED 3**：这是全屏程序在普通缓冲区里重绘，例如 Linux 上的 `top`，或者 TERM 不支持切换备用屏幕的程序。这时要**把当前屏幕内容推进回滚，而不是直接抹掉**（与 PuTTY 的做法一样），保证屏幕上出现过的内容永远不会丢。旧实现曾在 top 启动时把整个会话历史清空。
- 清除动作必须**按解析顺序立即执行**，不能等这批输出处理完再做：top 会在同一批输出里先清屏再画第一帧，如果事后才清，就会把这一帧也抹掉，导致 top 在下一次刷新前一片空白。
- 在 `clear` 那一批输出之后、另一批输出里出现的 ED 2，属于别的程序重绘，保留回滚。
- 备用屏幕没有回滚，带滚动区域的清屏也按普通方式处理。
- 用户主动清除缓冲区（⌘K）：清空屏幕、回滚和行元数据。

## 4. 命令分隔线

- **只用于本地会话**：在每条命令的提示符上方画一条 1 像素的分隔线，按命令把输出分块，便于阅读。远程会话的提示符没有我们的 shell 集成，通常不画（Warp 的做法也一样）。规则的本意是**有提示符标记才画**，不是按会话类型屏蔽：远端自己发送了 OSC 133（例如装了 shell 集成）时，同样画分隔线。
- 提示符的位置以 **OSC 133 A** 为准。zsh 重绘提示符时会重复发送 OSC 133 A，**同一行只能画一条**，否则半透明的线叠在一起会越来越亮。
- 线要**对齐设备像素**：落在半个像素上的 1 像素线会被抗锯齿成两条更淡的线，在终端背景上基本看不见。
- 全屏程序期间不画。
- 窗口宽度变化导致软换行重排后，要按新的行位置重新放置分隔线。
- 关闭时间戳栏时，分隔线照常显示，两者互不影响。

## 5. 命令跟踪与标签活动

用途：后台标签显示"运行中"；命令结束后保持"未读完成"的高亮，直到用户切回这个标签。Sender 也靠它判断"上一条命令是否已经返回"。

### 5.1 信号来源
1. **OSC 133（FinalTerm / iTerm2 shell 集成）**：A 提示符开始、B 输入开始、C 命令开始执行、D 命令结束。**有 OSC 133 时以它为准。** 本地 shell 由我们自己的集成发送（见 `local-shell.md`）。
2. **没有 OSC 133 时（常见于远程会话）**，按提示符特征推断：
   - 新提示符出现后的第一次按键，记下"输入起点"，也就是提示符结束的位置。此时 shell 还没有回显，光标正好停在提示符末尾。
   - 按回车视为提交，记下提示符的文本作为特征。
   - 下方再次出现相同特征的提示符，就认为命令已经返回。
   - 提交的命令文本**以屏幕内容为准**，不以原始按键为准，因为按键回显来自 shell。读取时要稍微延迟一下，等远端最后几个按键的回显（或 shell 擦掉自动建议的动作）到达；如果那时这一行已经不在了（例如命令输出里有 `clear`），就用提交瞬间的快照。

### 5.2 边界情况
- 命令运行期间的输入（sudo 密码、REPL、安装程序的提问、用 `q` 退出 top）属于这条命令，**不能当作新的命令行**，也不能替换掉正在等待的提示符特征。
- 如果"输入起点"已经不在光标正在编辑的那一行（例如被前台程序画过的屏幕覆盖，或者被回滚裁掉），就作废它。否则这条命令会一直显示"运行中"，后面的命令也会全部被它卡住。
- Ctrl+C 放弃当前行。
- 多行粘贴会执行我们没有看到用户输入的命令，输入起点作废。
- **终端自己的回应不算用户输入**：设备属性查询的应答、光标位置报告、颜色查询应答、模式状态、焦点通知、鼠标报告，都必须发给程序，但不能当成用户在打字。旧实现把这些算作输入，导致 TUI 一启动就被误判为用户操作。
- zsh 的右侧提示符和命令在同一行，中间用一串空格隔开：遇到连续 3 个以上的空格就截断，真实命令里很少出现这种情况。
- 以空格开头的命令不记入历史，与 shell 的 `ignorespace` 约定一致；过长的"命令"视为误捕获的输出，同样丢弃。
- 会话结束时，重置所有跟踪状态，正在等待的调用方立即返回。

### 5.3 对 Sender 提供的能力
- 发送前登记"即将发送某条命令"，以当前提示符作为完成特征；发送失败时撤销登记。
- 等待"当前命令返回提示符"，带超时；没有命令在运行时立即返回。

## 6. AI CLI 识别与轮次

Claude Code、Codex 这类工具会占住终端直到用户退出。如果按普通命令跟踪，标签会在整个工具会话期间一直显示"运行中"，没有任何信息量。识别出这类工具后，标签改为跟踪**助手的轮次**：助手在工作时显示忙碌，交还终端时显示完成。

### 6.1 识别规则（根据提交的命令行判断）
- **支持的工具**（按可执行文件名匹配）：claude、claude-code、codex、gemini、gemini-cli、aider、cursor-agent、copilot、amp、opencode、crush、goose、qwen、droid、openhands、grok。同一个工具的不同写法归为同一个工具。
- 取路径的最后一段，去掉 Windows 的 `.exe` 后缀。
- 跳过前面的 `VAR=value` 赋值。
- 跳过前缀命令及其选项：sudo、doas、env、command、exec、time、nohup、npx、pnpx、bunx、uvx。
- 识别两个词组成的包运行器：`npm exec`、`pnpm dlx` / `pnpm exec`、`yarn dlx`、`bun x`、`uv run`、`deno run`；也要能识别 npm 包名的写法，例如 `npx @anthropic-ai/claude-code`。
- `cd repo && claude` 算作启动；**管道里的不算**，从管道读输入的工具并没有在操作终端。
- **一次性运行不算会话**：
  - 选项：`-p`、`--print`、`--prompt`、`-m`、`--message`、`-h`、`--help`、`-v`、`-V`、`--version`；
  - 第一个参数是这些子命令：exec、run、mcp、update、upgrade、install、uninstall、doctor、config、login、logout、auth、help、version、completion、setup-token。
- 只有第一个位置参数可能是子命令。带引号的开场提示（`codex "run the tests"`）不算子命令。

### 6.2 轮次
- **用户在工具里按键，开启一个轮次**。工具工作时会持续刷新转圈动画和计时，这些输出让轮次保持开启。
- 工具**连续 2 秒没有输出**，视为这一轮结束，标签显示"完成"。2 秒明显长于这些工具的刷新间隔，同时又足够短，答案还在屏幕上时标签就会提示。
- **只有输出、没有用户按键时，不开启轮次**。否则空闲工具偶尔的重绘也会被当成在工作。
- 终端自己的回应（§5.2）不算按键。
- 通过 Sender 发给工具的文字，算作一个轮次。
- 工具运行期间，标签上显示它的标识；工具退出（命令返回）后撤掉标识。
- 工具的图标只使用许可允许的厂商标识，没有合适图标的使用通用图标，**不自己画别人的商标**。

## 7. 语义着色

借鉴 WindTerm：给**没有自带颜色的输出**按内容类别上色，提高可读性。

- **只给没有设置 ANSI 前景色的文字上色**。程序自己上了色的部分一律不动。
- 提示符内容（OSC 133 A 到 B 之间）保留 shell 原样，不做语义着色。
- 支持 Kanso 标签 OSC：`ESC ] 777 ; kanso-chip ; start BEL` / `ESC ] 777 ; kanso-chip ; end BEL`（实际序列不含空格）。区间内打印的单元格带标签位，同一行连续标签单元格画小圆角、贴近背景的底色；只有最新且尚未执行命令的提示符画标签。历史提示符行去掉标签和私有区图标，保持原字号，统一使用次要文字色 `terminal.gutterText`。属性随滚动、重排、回滚保留；缺少 end 时遇换行或 OSC 133 A 结束，未知 777 子命令忽略。内置提示符两行布局见 `local-shell.md` §5.2。
- 哈希只给十六进制片段上色，连字符、下划线和点都是边界；普通连字符单词不识别为路径或主机名。带扩展名的文件名使用独立的暖黄色类别，含 `/` 的目录路径保留路径色。
- **不修改字节流**，只在渲染层叠加颜色，所以光标移动、复制、全屏程序都不受影响。
- 识别的类别（示例）：路径和文件名、带引号的字符串、数字、版本号、日期和时间、UUID、哈希、IP / MAC 地址、主机名和域名、URL 和邮箱、命令行选项、环境变量、键值对的键、表头、权限位、大小和百分比、diff 的增删行、错误 / 警告 / 成功等日志级别、git 状态等。具体分类和配色**由新版重新设计**；每个类别在浅色和深色主题下各有一个颜色，与终端背景的对比度都不低于 4.5:1。
- 只给**可见区域及其上下少量余量**着色；同一行只有内容变化时才重新计算。
- 光标所在的逻辑行**还在被编辑**，不着色；光标离开后立即着色，不要等它滚走。
- 软换行的多行按一个逻辑行整体匹配，避免一个词被换行拆开后匹配不上。中日韩宽字符要按列宽对齐。
- 超长的行（压缩过的 JS、base64）跳过，不做匹配。
- **新输出要在第一次绘制时就已经着色**，不能先显示无色再变色。旧实现出现过 `ls -la` 闪一下的问题。
- 全屏程序期间不着色，退出后重新着色。
- 切换主题后重新着色。
- 设置里提供开关。
- **性能要求**：大量输出时，着色的开销每帧最多处理一屏，不能每行都计算一次。

## 8. 选区、复制与粘贴

### 8.1 鼠标
中键、右键的行为和"选中即复制"都在设置的"键盘与鼠标"页配置（`ui-shell.md` §7.1），所有平台相同。
- **右键**，两种模式，默认"弹出菜单"：
  - **弹出菜单**：弹出前先选中指针下的单词（VS Code 的做法）。菜单项为：复制、粘贴、全选、清除缓冲区、在 Filer 中显示工作目录。
  - **复制或粘贴**：有选区就复制，没有就粘贴，与 Windows 控制台的习惯一致，不弹菜单，也不预先选词。
  - macOS 的 Ctrl+单击不算右键，不受这个设置影响。
- **中键**，两种模式，默认"粘贴"：粘贴剪贴板内容（与粘贴命令走同一条路径，§8.3 的规则全部适用），或者"无动作"（给滚轮容易误按中键的用户）。
- 程序开启了鼠标上报时（vim、tmux、htop），点击交给程序处理，不看上面两个设置。**所有平台都按住 Shift 绕过**，由终端自己处理选择、右键和中键，与 xterm、Ghostty、Alacritty、Windows Terminal 一致。macOS 不用 Option，因为 Option+拖动留给矩形选择。
- 拖动选择在任何情况下都不能"粘住"：如果丢失了松开事件，下一次按下鼠标时要先结束上一次拖动。

### 8.2 复制
- "选中即复制"是开关，默认关闭；设置页和编辑菜单两处入口改的是同一个值。开启后，松开鼠标完成选择、并且确实有非空选区时自动复制；单击不产生选区时不复制。
- 复制选区。**写入剪贴板失败必须提示用户**，否则用户看到选区还在，以为已经复制成功。
- 复制、粘贴、全选都可以重新绑定快捷键。如果复制键被绑定为普通的 Ctrl+字母，那么没有选区时这个键要照常发给 shell（Ctrl+C 仍然用于中断）；其他组合键则直接吃掉，避免变成多余的控制字符。

### 8.3 粘贴
按以下顺序判断剪贴板内容：
1. **文件**（例如在 Finder 里复制的文件）：把路径用空格连接后粘贴。
   - 在 AI CLI 会话里，**原样粘贴路径**，让工具能识别成附件。
   - 普通 shell 里，**转义空格等元字符**，避免粘贴后参数被拆开或被 shell 展开。POSIX shell 用反斜杠转义；Windows 的 PowerShell 用反引号转义，两者需要转义的字符集不同。
2. **只有图片**并且处于 AI CLI 会话：不粘贴文字，而是**发送该工具自己的图片粘贴键**，由工具自己读取系统剪贴板。macOS / Linux 发 Ctrl+V；Windows 上只对 Claude 发 Alt+V。
3. **文本**：如果程序开启了 bracketed paste，就用它包裹后粘贴。
- 读取剪贴板失败时，在终端面板里提示，不能静默失败。
- 文件传输期间禁止粘贴（§1）。

## 9. 按键

- **Option/Alt + ←/→ 按单词跳转**：macOS 发送 `ESC b` / `ESC f`；其他平台发送 Ctrl+方向键对应的序列，Alt+↑/↓ 也映射为 Ctrl+↑/↓。zsh、bash 默认没有绑定纯 Alt 修饰的方向键序列，所以需要这样转换。
- 普通的 Ctrl+字母和 Alt+字母属于 shell 的控制字符和 readline 的 Meta 层，**除非用户主动绑定，否则永远不拦截**。
- macOS 上"Option 作为 Meta 键"做成设置项，可选值为：关闭 / 仅左 Option / 仅右 Option / 两侧都是。**默认关闭**，保持系统输入特殊字符的习惯；上面的 Option+←/→ 单词跳转不受这个设置影响。
- ⌘ 组合键不会发给 shell。快捷键表见 `ui-shell.md`。
- 支持 kitty keyboard protocol（新版新增），由程序主动开启。Claude Code、Codex 等工具靠它区分 Shift+Enter（换行）和 Enter（提交）。

## 10. 链接

- 自动识别输出中的 URL，并支持 OSC 8 超链接（新版新增）。
- **只有按住 ⌘（macOS）或 Ctrl（其他平台）点击时才打开**，避免误点打开网页，与原生终端的行为一致。

## 11. 搜索

- ⌘F 搜索缓冲区，⌘G 查找下一个。
- 高亮所有匹配项，显示"第几个 / 共几个"。
- 输入过程中进行增量搜索：保持当前匹配项选中，不跳到下一个。
- 新输出到来时，匹配结果随之更新。
- 切换主题后，高亮颜色随之刷新。
- 关闭搜索时清除所有高亮，并停止随输出重新搜索。

## 12. 工作目录上报

- 支持的序列：
  - OSC 7：`file://主机/路径`。路径可能经过百分号编码，也可能没有（很多提示符脚本直接写 `$PWD`），解码失败时按原样使用。
  - OSC 1337：`CurrentDir=路径`（iTerm2）。
  - OSC 9;9：路径两侧的引号可有可无（ConEmu / Windows Terminal）。
- 只保留最新的一次上报，同时记录主机部分。
- 用于"在 Filer 中显示工作目录"（⌘J），优先级高于系统查询和服务器查询（见 `ssh.md` §10）；同时用作提示符的标志，因为有些提示符是空的或者自定义的，只靠屏幕文字识别不出来。
- 会话结束或重新连接时清空，重新连接后 shell 回到主目录，旧的上报不再有效。

## 13. 会话结束

- 锁定终端：键盘、粘贴、补全都不再发往会话，隐藏光标，避免面板看起来还在等待输入。
- 重新连接时解除锁定。
- 正在进行的文件传输立即失败，不必等它自己超时。

## 14. 补全弹窗的交互

补全的数据来源见 `completion.md`，这里只规定弹窗的交互：
- **被动状态**：弹窗显示时，所有按键照常发给 shell，↑ 翻历史、远端 shell 自带的 → 接受建议都不受影响。只有 ↓ 会进入列表，Esc 关闭弹窗，Tab 选第一项或者接受当前选中项。
- 没有弹窗、也没有正在进行的补全请求时，Tab 交给 shell 自己的补全。
- 补全结果可能是异步的（远程目录要经过一次网络往返）：只采用**最新一次请求**的结果；结果到来之前**先扣住 Tab**，不交给 shell，免得两套补全打架。
- 只读取光标之前的输入，所以 fish、zsh-autosuggestions 显示在光标后面的建议不会反过来干扰我们的补全。
- **接受某一项时，只替换这一项声明要替换的范围**（路径补全只替换当前单词，命令补全替换整行），并且以模拟按键的方式发送（每个码点一个退格），让 shell 自己编辑这一行，它的历史和撤销功能才能正常工作。
- 弹窗水平方向对齐输入的起点，垂直方向放在光标行下方，下方空间不够时翻到上方。
- 新的按键会让弹窗回到被动状态，进入列表必须是用户的主动操作。

## 15. 显示设置

- 光标形状（块状 / 下划线 / 竖线）及是否闪烁，默认闪动竖线（2026-11-16 产品决定：块状太宽）。
- 字体族与字号（默认 14）。终端只列出等宽字体，同时允许手动输入任意名称，方便使用私有构建的 Nerd Font。
- 行距位于字号下方，范围 1.0–2.0，默认 1.2，步长 0.05。单元格高度为字体自然行高乘以行距倍数，额外空间上下平分，字形垂直居中；所有按行定位的装饰、光标、选区、时间戳、输入法与补全弹窗跟随单元格高度。
- Powerline 分隔符（U+E0B0–E0BF）由终端按单元格几何自己绘制：实心形状撑满整个单元格（含行距），与相邻色块无缝拼接，不随粗体 / 斜体变形，也不依赖是否安装 Nerd Font；其他 Nerd Font 图标仍按原有回退顺序处理。
- 回滚行数；调小以后立即丢弃超出的部分。
- 最低对比度保护（见 `architecture.md` 主题一节）。
- 被隐藏的标签不占用渲染资源（GPU surface 等），切回时再创建，切换延迟不能被察觉。

## 16. IME 验收场景

以下场景都来自旧版的真实问题，新版必须全部通过（用微信输入法、豆包输入法、搜狗输入法、系统拼音分别测试）：
- 中文输入法处于英文模式时快速输入，连按的第二个键不能丢。
- 按住 Shift 后输入的第一个全角标点不能丢。
- 用空格确认拼音词组时，不能重复上屏。
- 两次组字在极短时间内先后完成，两次的内容都要上屏，不能丢一次。
- 已经上屏的内容不能被重复发送。
- 组字期间，回车、退格、Esc 交给输入法处理，不发给 shell。
- 候选框跟随光标位置。

## 17. 性能要求

- 解析吞吐、按键延迟、回滚搜索的目标见 `design.md` 性能目标。
- 时间戳栏、分隔线、语义着色这三项功能全部开启时，`seq 1 300000` 这类大量输出的吞吐下降**不超过 10%**（旧实现曾因为每行触发一次处理，吞吐跌到约每秒 1 万行）。

## 18. 验收用例

- 缓冲区满了以后，行号继续增长。
- Linux 和 macOS 两种顺序的 `clear` 都会清空回滚，并让行号从 1 重新开始；单独的 ED 2 保留回滚。
- Linux 上启动 `top`：会话历史不丢失，第一帧正常显示。
- zsh 重绘提示符时，分隔线不会重复叠加。
- 运行 `sudo` 输入密码、`top` 中按 `q` 退出等情况，不会误记成新的命令。
- TUI 启动时发出的终端查询应答，不会开启 AI 轮次。
- `npx @anthropic-ai/claude-code`、`sudo -E claude`、`cd x && codex` 都能识别为 AI 会话；`claude -p hi`、`codex --version`、`echo x | claude` 都不算。
- 在 AI 会话里粘贴图片，工具收到的是它自己的粘贴键；在普通 shell 里粘贴带空格的文件路径，路径会被正确转义。
- 语义着色不会改变程序自己上色的文字，`ls -la` 不会先无色再变色。
- 中英文 IME 场景（§16）全部通过。
- 鼠标设置每种组合都按 §8.1 生效：右键"复制或粘贴"模式下有选区复制、无选区粘贴且不弹菜单；中键"无动作"时点击不粘贴；vim、tmux 开启鼠标上报时两个设置都不生效，按住 Shift 后才生效。
- 选中即复制开启后，拖选或双击选词后松开即写入剪贴板；单击没有产生选区时不改动剪贴板。设置页与编辑菜单的勾选状态始终一致。

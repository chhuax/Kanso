# 命令补全规格

覆盖终端命令补全的历史、路径、内置命令、子命令和选项数据来源，触发时机，本地与 SSH 的差异，以及性能和失败边界。弹窗的按键、选中、位置、接受与替换交互全部见《终端规格》§14，本文不重复。

核对基准为 2026 年 11 月 15 日旧仓库的当前工作副本，包括当时已有的未提交改动，并核对相关测试的既有断言。本次未实测真实 SSH 往返、用户 shell、海量目录或商店版授权；文末场景是后续验收要求，不代表已经通过。

未标待定的条目提炼旧版已有行为；已经由其他规格明确的新版行为沿用该规格。**[待定]** 表示存在缺陷、语义不清或缺少验证，正文描述旧版现状并不要求新版照搬。

### 待定项

| 编号 | 旧版现状或疑点 | 需要决定的行为 |
|---|---|---|
| D1 无法确定目录或主机 | 工作目录取得失败时仍可能按其他默认目录列举；本地终端内手动登录其他主机后，目录上报也可能被当成本机路径 | 无法确认当前 shell 目录及所属机器时，路径候选是否停止；如何展示暂不可用，能否使用家目录以及必须如何标明 |
| D2 历史候选与参数位置 | 历史按光标所在词匹配，在参数位置也可能出现整条命令；旧版接受时可能只替换一个词，和《终端规格》§14 的整行替换约定冲突 | 历史整行候选是否只在命令位置提供，或在其他位置采用明确的整行替换；不得默认为用户拼接另一条命令 |
| D3 路径适用范围 | 部分普通参数没有路径候选，部分工具子命令把分支、资源名称当路径；切换目录时也会列出普通文件 | 哪些命令与参数位置提供路径，目录专用位置是否只显示目录；未知命令、可执行路径及其他 shell 的路径写法如何处理 |
| D4 复杂 shell 输入 | 旧版只处理部分引号、转义、命令连接和简单前缀；带选项的提权前缀、引号内分隔符、重定向及 Windows 写法没有完整保证 | 首版支持的输入边界；识别不清时是否停止该类候选，以及怎样保证不改变用户原输入含义 |
| D5 请求延迟与大目录 | 远端目录、工作目录或名称查询变慢时，历史和内置候选也可能一起等；旧版无明确补全超时或大目录读取上限 | 可接受延迟、何时结束等待，是否先显示已有候选，以及大目录的读取量和耗时边界；数值尚未定，不编造已达标指标 |
| D6 内置命令的适用性 | 内置候选包含会改变文件、Git 状态或服务状态的命令，也不检查当前机器是否安装相应工具；候选并非统一只读 | 保留哪些类别，如何说明适用环境；不能把“来自内置库”当作安全、已安装或执行成功的承诺 |
| D7 Kubernetes 名称语义 | 旧版仅在本地提供配置中出现的名称；名称无匹配时可能回退到路径，同名选项也可能在其他命令里触发名称候选 | 候选是否严格限定 kubectl 的相应参数；空结果是否允许混入文件名，以及指定另一份配置后名称应来自哪里 |
| D8 历史失败与长度 | 历史读取和保存失败大多静默；清空失败会提示，但可能只清掉当前看到的内容；中文长命令的可记录长度在不同环节口径不一致 | 如何提示历史读取、保存、清空失败及恢复；统一遵循《存储、导入与导出规格》§5 的 500 字符口径，明确字符计数，不能宣称旧版已一致 |

### 决定（2026-11-15，新版按此实现，覆盖正文中对应的待定描述）

- D1：无法确认当前 shell 的工作目录（没有有效上报、查询也失败）时不提供相对路径候选，不回退到家目录；绝对路径和 `~` 开头的路径照常。本地终端里手动 ssh 到其他机器后的上报，按《终端规格》§12 的主机判定处理，判定不是本机时不提供路径候选。
- D2：历史和内置完整命令只在命令位置（每个命令片段的第一个词，光标前没有参数）提供，接受时替换该命令片段整段；参数位置不出现整条命令。
- D3：路径只在一组固定命令的参数位置提供（cd、pushd、ls、cat、less、tail、head、vim、vi、nano、code、cp、mv、rm、mkdir、touch、chmod、chown、source、tar、scp 的本地参数等）；cd、pushd、mkdir 的位置只列目录。未知命令仅在当前词含 `/` 或以 `~`、`.` 开头时提供路径。Git 只在 add、checkout --、restore、rm、diff 后提供路径，不伪造分支名。
- D4：首版支持单引号、双引号、反斜杠转义、`&&`、`||`、`;`、`|` 分段，以及不带选项的 sudo、env、time、nohup 前缀和 `VAR=value` 赋值；遇到未闭合引号、heredoc、命令替换、重定向目标等识别不清的情况，该次不提供任何候选，绝不改动用户输入。
- D5：历史和内置候选先显示，不等路径；路径/名称查询本地 300 毫秒、远端 1.5 秒内未返回则放弃本次该来源；单个目录最多读取 2000 个条目后停止。
- D6：保留内置库，限定为 kubectl、docker、git、systemctl、journalctl 的常用写法，数量从简；候选说明里不标注“安全”或“只读”，不检查是否安装。
- D7：不查询集群，不列真实资源实例。kubectl 子命令、资源种类、选项在任何位置照常提供，不需要先写 `--context`、`-n`。kubeconfig 里的上下文、命名空间名称在这些位置提供：kubectl 的 `--context`、`-n`、`--namespace` 值位置，`kubectl config use-context`、`kubectl config set-context`（上下文名）、`kubectl config delete-context`，以及 `kubectx`、`kubens` 的参数位置。名称无匹配时不回退路径；同一行写了 `--kubeconfig` 时不提供名称候选。名称来自 `KUBECONFIG` 环境变量列出的文件或 `~/.kube/config`。
- D8：长度按 Unicode 字符（码点）计数，超过 500 不记录；历史读取、保存失败静默省略；清空失败在状态栏报告，清空要清掉存储里的全部条目而不只是内存。

共用约定直接引用：

- 历史采集、密码与前台程序输入的排除、工作目录上报、会话结束：见《终端规格》§5、§12、§13。
- 弹窗完整交互：见《终端规格》§14；这里只定义候选内容与产生条件。
- 历史容量、保留、清空和数据保护：见《存储、导入与导出规格》§5。
- 本地工作目录查询与 SSH 工作目录查询：分别见《本地 shell 规格》§6、《SSH 规格》§10。
- [MAS] 本地目录和 Kubernetes 配置的访问范围：沿用既有沙盒授权规则；本次没有追加发行版可用性结论。

## 1. 开关与触发时机

### 1.1 开启和关闭

- 编辑菜单中的“命令建议”控制应用自己的补全，并同时控制历史采集；默认关闭，用户开启后记住选择，作用于本地和 SSH 终端。
- 关闭时停止显示应用候选并停止新增历史，不删除已经记录的历史；重新开启后可继续使用已保存内容。清空历史是独立操作，不等同于关闭建议。
- 开关保存失败时，旧版仍在本次运行采用所选状态，但没有明确的保存失败反馈；不保证下一次启动仍记住该次选择。

### 1.2 自动请求的条件

- 开启建议后，用户在普通终端命令输入行键入或编辑文本，按当前光标之前的输入更新候选；依赖 shell 已经回显的内容，远端回显慢时，候选可能晚于按键出现。
- 历史和内置命令至少需要两个非空白字符才参与匹配，且候选至少比用于匹配的输入多三个字符；单字母或没有明显补全收益时不提供这两类候选。
- 子命令、选项和路径不套用上述最少字符规则；已经输入一个受支持工具再留出参数位置时，即使该位置还没有文字，也可以显示上下文候选。
- 只针对正在编辑且能确定输入起点的普通命令行提供候选；无法确认输入范围、当前行已经被程序覆盖、会话结束或进入全屏终端程序时，不应把程序输出当成待补全命令。
- 提交、放弃当前输入、切换到不适用的终端状态时，旧输入的候选失效；重新开始编辑后按新输入重新取候选。窗口和候选交互遵循《终端规格》§14。
- 纯 SFTP 会话没有终端输入，不提供命令补全。锁定和终端传输占用时不得通过补全写入会话，遵循《终端规格》§1、§13。

## 2. 候选来源与合并

- 旧版有四类来源：应用记录的历史、当前会话可见的路径、应用随附的常用完整命令、受支持工具的子命令与选项；本地还可提供 Kubernetes 配置中的上下文和命名空间。
- 已识别命令语境时，工具自身词汇和适用的名称候选优先，再考虑路径，其后为历史，最后才是内置完整命令；普通命令位置由历史领先，内置库补充。
- 一次最多显示 8 条候选。合并后形成相同补全结果的内容只显示一次；同一历史命令在不同主机用过也不重复占行。
- 数据源为空、不可读或失败时，该来源没有候选，不能编造命令、目录、分支、资源或命名空间。旧版一般静默省略，不弹错误对话框；需要可见失败提示的范围见 **[待定 D1、D5、D8]**。
- 某来源缓慢时，旧版可能使其他来源的结果一起等待；不能把八条显示上限当作查询已完成或操作一定快速的保证，见 **[待定 D5]**。

## 3. 命令历史

### 3.1 记录什么

- 使用用户在 Kanso 终端中提交过的命令，历史可跨终端和应用重启使用；不主动读取或导入 shell 自己的历史，也不把 Sender 已保存命令库自动当成补全库。
- 命令以终端实际回显为依据；远端回显尚未完整到达时，旧版稍等后再确认内容，输入行已经消失则采用提交时可读到的内容。命令是否执行成功不是进入历史的前提。
- 以空格开头的命令不记录；空命令和明显过长内容不记录。密码回答、前台程序交互、多行粘贴和系统终端回应的识别，复用《终端规格》§5，不额外推测成用户命令。
- 旧版对同一行右侧提示符的排除，会把连续多个空格之后的部分一并截掉，真实命令包含这类空格时可能记录不完整；复杂输入的边界见 **[待定 D4]**。
- Sender 发出的内容能够参与命令活动判断，但旧版没有独立、完整的 Sender 历史采集保证；不能承诺每次批量或重复发送都会增加一条补全历史。

### 3.2 匹配、去重与排序

- 匹配区分大小写，支持从命令开头匹配和在命令中间包含输入；不是任意不连续字符的模糊匹配。
- 排序依次优先命令开头匹配、同一主机来源、最近使用。同一文本来自多台主机时，只保留排位最优的一项；旧版虽然记录使用次数，但不按次数优先。
- 历史跨主机共享，同主机只是排序优先，不是只看本机或当前服务器。需要按机器隔离历史时，不能把现有排序描述成隔离能力。
- 旧版实际按光标所在词匹配历史，因此参数位置也可能出现完整历史命令；候选内容与整行替换的协调见 **[待定 D2]**，接受交互以《终端规格》§14 为准。

### 3.3 容量、清空与失败

- 最多保留 5000 条，超过后淘汰最久未使用项；再次使用会更新最近使用时间，常用旧命令不会仅因记录得早被淘汰。
- 每条最多 500 个字符，超过不记录，规则以《存储、导入与导出规格》§5 为准；旧版中文长度口径不一致的问题见 **[待定 D8]**。
- “编辑 → 清除命令历史…”清除全部应用历史，旧版操作前询问确认；取消不清空。清空不删除内置命令，也不删除 Sender 保存项，所以补全不一定变成空列表。
- 历史读取失败时，旧版仍可提供内置及其他来源候选；保存失败时，本次运行可能仍看到刚记录的命令，但不保证重启后存在；清空失败时状态栏报告失败，也不保证重启后仍为空。其他历史失败的反馈与恢复见 **[待定 D8]**。

## 4. 路径补全

### 4.1 来源和定位

- 本地 shell 候选来自本机文件系统，SSH 终端候选来自该活动连接的远端文件系统；Filer 当前浏览位置不决定终端补全位置。
- 优先使用当前 shell 上报的工作目录；没有有效上报时，按本地或 SSH 既有查询规则取得目录。只在路径候选适用时查询，不能为一个普通历史匹配而反复定位目录。
- 相对路径应对应当前 shell 所在位置，绝对路径对应本会话所属机器。旧版在无法取得目录时的默认位置、嵌套登录后的主机归属和其他 shell 路径格式存在歧义，见 **[待定 D1、D4]**。
- 目录不存在、无读取权限或远端文件服务不可用时，该目录没有路径候选；不将本机同名目录冒充远端目录。旧版没有为每次失败弹窗，是否说明暂不可用见 **[待定 D1、D5]**。

### 4.2 何时提供路径

- 旧版为一组常见的目录导航、文件查看、编辑和文件操作命令提供路径；部分工具只在特定子命令后提供，不是所有命令、所有参数都查目录。
- 当前词是选项名称时，不在选项名称位置混入文件候选；已有工具子命令或参数名称候选时，先采用更符合该位置的候选。
- 未知命令不会仅因用户正在输入一个看似路径的词就保证提供补全；旧版不枚举可执行程序搜索目录，也不发现用户别名或自定义 shell 补全。
- 某些 Git、容器和 Kubernetes 操作的位置同时可能是分支、对象名或路径；旧版对这些位置的判断不完整，不能声称已提供真实分支、容器或集群对象名称，适用范围见 **[待定 D3]**。

### 4.3 路径候选内容

- 只列出当前要补全目录的直接子项，不递归搜索整个目录树；按已输入名称前缀区分大小写匹配。
- 目录候选带末尾目录分隔标识；目录优先，同类再按名称排序。旧版还对名称继续延伸和紧接扩展分隔符的情况作区分，排序不是访问频率。
- 默认不列隐藏条目；用户已经明确键入隐藏名称的前缀时，才参与匹配。仅键入当前目录或上级目录符号时，旧版不把它当作要求列出所有隐藏项。
- 旧版在切换目录命令的位置也会列出匹配的普通文件，并非只显示可进入目录；是否过滤见 **[待定 D3]**。
- 带空格、引号或特殊字符的路径，其接受结果必须保留原有参数含义；旧版只覆盖部分引号、转义和路径形式，不能把有限例子写成所有 shell 均可用，范围见 **[待定 D4]**。具体接受操作不在本规格展开。

## 5. 内置命令与子命令

### 5.1 常用完整命令

- 内置库提供 Kubernetes、Docker、Git、系统服务和日志管理的常用命令写法，用户尚无历史时也能出现；按随应用提供的类别次序补充，不学习成系统自动发现的命令清单。
- 与历史一样，按包含输入匹配、区分大小写，满足两个非空白字符及至少增加三个字符的门槛；与历史相同的结果只出现一次，历史优先。
- 部分候选留下待填写参数的位置；不自动填入真实服务器、资源或文件名称，也不因出现候选就执行工具。
- 旧版不检查当前机器或服务器是否安装该工具、命令适用的操作系统和工具版本。内置项包含会改变状态的操作，具体保留范围见 **[待定 D6]**，不能标成全部只读或无风险。

### 5.2 工具自己的词汇

- 旧版专门提供 Git、kubectl 的子命令和选项名称；kubectl 另有常见资源种类、单复数及缩写。选项可以附简短用途说明，资源缩写可以附完整种类说明。
- 子命令、资源种类和选项按当前词的开头匹配，区分大小写；这些词汇随应用提供，不按每次输入查询工具帮助或服务器。
- Git 的首级子命令、选项能够提供；仓库实际分支、标签、远端、提交名称以及更深层子命令没有专门的动态来源。kubectl 的资源种类不等于当前集群真实存在的资源实例。
- 命令连接或管道中，旧版会尝试按光标所在片段的工具判断；能跳过部分简单赋值和命令前缀，但复杂输入及带选项的前缀没有完整保证，见 **[待定 D4]**。
- 工具没有专门候选时，仍可按适用条件显示历史、内置命令或路径，不报告该工具已实现完整补全。

### 5.3 Kubernetes 上下文与命名空间

- 本地终端在对应名称参数位置可以提供本地 Kubernetes 配置中的上下文和命名空间；配置指定多个来源时合并名称、去重并按名称排序。没有配置名称时，旧版仍提供默认命名空间。
- 名称只代表配置中已出现的内容，不代表已连上集群，也不列举集群中所有命名空间；不查询 Pod、服务或其他真实资源实例，不因补全发起集群登录。
- SSH 终端不使用本机的 Kubernetes 名称，也没有远端配置名称的专门来源；仍能提供与机器无关的工具词汇。
- 本地配置缺失或不可读时，不虚构上下文；旧版会省略不可读来源并保留默认命名空间。不能将这种默认候选描述为已经验证远端权限或集群存在。
- 旧版同名选项可能在非 kubectl 命令中触发名称候选，没有名称匹配时也可能落入路径候选；显式选择另一份配置后的来源同样不明确，统一见 **[待定 D7]**。

## 6. 本地与 SSH 的差别

| 内容 | 本地 shell | SSH 终端 |
|---|---|---|
| 历史 | 应用共享历史，本机来源优先 | 应用共享历史，相应主机来源优先 |
| 路径 | 当前本地 shell 对应的本机目录 | 当前活动 SSH 连接可访问的远端目录 |
| 工作目录 | shell 上报或本地查询 | shell 上报或远端查询，能力边界见《SSH 规格》§10 |
| 内置完整命令、Git 与 kubectl 词汇 | 可提供，不检查实际安装情况 | 同样可提供，不表示服务器支持 |
| Kubernetes 配置名称 | 可从本地配置取得 | 不拿本地配置冒充远端，没有专门的远端名称来源 |
| 延迟与失败 | 受本地目录及授权影响 | 另受回显、网络、目录定位和远端文件服务影响 |

- 两个 SSH 标签即使名称或服务器地址相同，路径也必须属于各自活动连接；重连后的旧目录不能被当作新 shell 的已确认位置，遵循《终端规格》§12、§13。
- 从本地 shell 手动登录 SSH、进入容器或启动嵌套 shell，不等于应用自动获得对应文件服务；不能据终端文字承诺这些环境的路径补全已支持，见 **[待定 D1、D4]**。
- [MAS] 未获目录或配置读取权限时，相应来源可能不可用；输入、已有历史和内置词汇仍可使用。授权范围与失效后的处理沿用既有沙盒规格，不把 Direct 版的读取能力直接视为已实测的商店版结果。

## 7. 性能、时效和失败边界

- 候选最多 8 条，只对当前输入产生候选；读取新目录不改变 shell 的工作目录，也不向终端输入查询命令。
- 连续输入同一目录前缀时，不应让每个字符都等待一次完整远端读取。旧版同一目录结果可在约 1.5 秒内复用，未有新上报的工作目录可约 2 秒内复用，Kubernetes 配置名称可约 30 秒内复用；这些是旧版允许短暂滞后的尺度，不是网络延迟保证。
- 刚创建、删除或更名的条目不保证立即出现在候选中；超过相应短暂复用时间后，再次请求应能看到新内容。候选出现后条目又被删除，不代表后续命令仍能成功，实际结果由 shell 或工具报告。
- 只为确实使用路径或配置名称的位置读取外部数据；普通历史和内置词汇查询不要求访问服务器、扫描可执行程序目录或读取文件正文。
- 旧版虽然最多显示 8 项，但会先取得整个目录再筛选，大目录仍可能耗时、占用较多资源；没有已经验证的最大目录条数、内存上限或毫秒级响应指标。最终性能要求见 **[待定 D5]**。
- 远端超时或某个来源报错不能改变用户已键入的命令。旧版整体请求报错时不显示该次候选；若来源一直不返回，缺少明确的补全等待上限，见 **[待定 D5]**。
- 连续输入、切换目录或结束会话时，过时结果不能污染新输入；结果采用与请求等待的交互规则统一遵循《终端规格》§14，不另定义第二套按键行为。
- 补全不应因大量终端输出反复扫描全部回滚，也不应为后台无输入标签持续请求目录。旧版普通输入读取也有约十余个折行的边界，超长、多行和复杂输入的精确支持范围尚需随 **[待定 D4、D5]** 明确，不宣称无限长度支持。

## 8. 验收用例

以下用例用于后续实现，未在本次文档整理中运行；待定项需有明确决定后再确定最终结果。

- 首次使用默认关闭；开启后当前及其他终端开始提供适用候选并采集历史；关闭立即停止应用建议和新增采集，重新开启仍有原历史。
- 一个字符或无补全收益时不出现历史和内置候选；工具参数空位仍可出现子命令或路径候选，不能把两个字符门槛套到所有来源。
- 同一命令在多个主机使用后只占一项；命令开头匹配优先于中间包含，同主机、最近使用按顺序排序；大小写不同不误匹配。
- 空格开头、密码回答、前台程序输入和终端自身回应不误入历史；中文长度、连续空格和复杂命令的边界按 D4、D8 决定后验收。
- 历史达到 5000 条后淘汰最久未使用项；清空前取消不丢数据，确认后内置和 Sender 命令不被一起清除；持久保存、清空失败按 D8 的反馈规则验收。
- 本地和 SSH 在同名目录有不同条目时，候选各自来自当前终端所在机器；改变 Filer 浏览位置不改变补全目录；无目录、嵌套登录或重连后按 D1 的决定处理。
- 路径匹配当前词前缀、目录优先、默认不显示隐藏项；明确输入隐藏前缀后出现。目录专用位置、未知命令、特殊字符和 Windows 路径按 D3、D4 决定后验收。
- Git 和 kubectl 子命令、选项及资源种类可用；没有真实分支、Pod 或容器数据时不伪造实例名称。内置命令适用范围按 D6 验收。
- 本地配置中的上下文、命名空间去重出现，SSH 不混入本地名称；缺失配置、指定另一份配置、其他命令的同名选项和无匹配值按 D7 的决定验收。
- 大目录、远端高延迟、文件服务不可用时，输入可继续；并分别测量候选等待与资源占用，按 D5 决定的数值验收，不能以八条显示上限代替性能测试。
- 最新请求、旧结果失效和接受替换范围复用《终端规格》§14 的验收；本规格不新增弹窗按键要求。

# SSH 规格

覆盖 SSH 终端会话和纯 SFTP 会话共用的连接层，以及 SFTP 文件操作。OpenSSH 配置导入、终端编码、本地 shell 另立规格。

## 1. 会话配置项

一个已保存的 SSH / SFTP 会话包含：
- 名称、颜色、所属分组。
- 主机、端口（默认 22）、用户名。主机或用户名为空时，连接前直接报错，不发起网络请求。
- 认证方式：密码、私钥、ssh-agent，三选一，默认是密码。
- 密码；私钥路径及其口令。
- 跳板机：引用**另一个已保存的 SSH / SFTP 会话**，不是单独填写的地址。
- 终端编码、远端 locale（见 §6）。

一个配置可以同时打开多次，每次打开都是一个独立的活动会话。

## 2. 传输层与算法

### 2.1 算法顺序
- **现代算法排在前面**，顺序参照 OpenSSH 的默认列表：
  - 密钥交换：包含后量子混合的 mlkem768x25519、curve25519；**还要包含 NIST ECDH 曲线（nistp256/384/521）**。很多网络设备只支持这几条曲线，russh 默认列表里没有，需要手动加上。
  - 加密：chacha20-poly1305、aes-gcm（128/256）、aes-ctr。
  - MAC：hmac-sha2 的 ETM 与非 ETM 版本。
- **旧算法排在所有现代算法之后**：
  - 密钥交换：diffie-hellman-group14-sha1、diffie-hellman-group-exchange-sha1、diffie-hellman-group1-sha1。group14 要排在 group-exchange 前面，原因是用 group-exchange 时，协商完方法才知道群有多大；如果设备的群小于下限，连接会直接失败，没有机会退回到它同样支持的固定 2048 位群。
  - 加密：aes128/192/256-cbc。
  - MAC：hmac-sha1，含 ETM 版本。
  - 主机密钥：允许 ssh-rsa（SHA-1 签名）。
- 3des-cbc、hmac-md5、ssh-dss **不支持**。
- 列表里要带上 RFC 8308 扩展协商标记和 OpenSSH strict-kex 标记（用于防御 Terrapin 攻击）。
- group-exchange 能接受的最小群为 2048 位，与 OpenSSH 的下限一致。

**为什么允许旧算法**：交换机、路由器、防火墙上的 SSH 实现往往停留在 SHA-1 和 CBC，而网络工程师正是这类客户端的主要用户。因为由客户端的顺序决定最终选择，旧算法排在最后，只要服务器支持更好的就会用更好的。双方的算法列表都包含在主机密钥签名的交换哈希里，中间人无法删掉好的选项来逼迫降级。

### 2.2 旧算法提示
- 记录每一跳（包括跳板机）实际协商出的旧算法。
- 只要有任何一跳用了旧算法，状态栏就显示 **Legacy SSH**。悬停时列出是哪个 `host:port`、用了哪些算法。
- 用了 AEAD 加密（chacha20-poly1305、aes-gcm）时，MAC 没有实际使用，不能因为协商结果里出现了 hmac-sha1 就报旧算法。

### 2.3 协商失败的报错
没有共同算法时，报错要说清是哪一类（密钥交换、主机密钥、加密、MAC、压缩），并**列出服务器提供了哪些**，去掉扩展标记那类伪算法。不要把客户端自己的长列表放在前面，用户真正要看的是服务器那一份。

### 2.4 连接参数
- 每 30 秒发一次 keepalive，连续 3 次没有回应就判定断线；不设空闲超时。
- 关闭 Nagle 算法（TCP_NODELAY），保证交互输入延迟低。

## 3. 主机密钥

策略相当于 OpenSSH 的 `StrictHostKeyChecking=accept-new`：
- **未知主机**：记录下来，然后继续连接。
- **已知主机，并且密钥匹配**：继续连接。
- **已知主机，同一种算法的密钥变了**：拒绝连接，不打开任何通道。向用户展示主机、端口、新密钥的类型和 SHA256 指纹、旧记录所在的位置（文件和行号），并提供"接受新密钥"的选项。
- **已知主机，但出现了一种新算法的密钥**：当作首次见到这种算法，记录下来并继续连接。
- known_hosts 文件不存在或解析失败时，当作未知主机处理，并尝试写入。
- **用户接受变更后**，删除该主机的**所有**旧记录，再写入新密钥，效果等同于先 `ssh-keygen -R` 再首次连接。理由是用户已经认定这个地址换了一台机器，其他算法的旧密钥也一并失效。
- 非 22 端口的记录格式是 `[host]:port`，与 OpenSSH 兼容。
- 跳板链中**任意一跳**发生密钥变更，都在那一跳停下，并报告是哪个主机。用户接受后重新发起连接。
- 报告行号时，要和用户用编辑器打开文件看到的行号一致，**注释行也要计数**。部分解析库不计注释行，需要换算。

**Direct 版**：读写 `~/.ssh/known_hosts`，与系统自带的 ssh 共用。
**[MAS]**：
- 记录保存在应用容器内。
- 提供"从 `~/.ssh/known_hosts` 导入"，需要用户在打开面板里授权这个文件。
- 设置里可以查看、删除已记录的主机。

## 4. 认证

### 4.1 流程
1. **先发一次 `none` 认证**。这一步既是向服务器询问它支持哪些方法，也能处理不需要认证的设备：有些没设 root 密码的路由器（dropbear）会直接放行 `none`，却拒绝空密码。服务器回复成功就直接结束。
2. **用配置里的方式认证**：
   - **密码**：发送保存的密码。
   - **私钥**：加载密钥文件，有口令就用口令解密。路径支持 `~/` 开头。对 RSA 密钥，要先询问服务器支持哪种签名哈希（rsa-sha2-256/512），再签名，因为新版服务器会拒绝 SHA-1 签名。
   - **agent**：依次尝试 agent 里的每个身份（证书身份取其公钥）。服务器完全接受，或者接受但还需要下一个因素（partial success），都停止尝试，后续认证沿用这个身份。
3. 如果服务器回复失败，但**剩余可用方法里有 keyboard-interactive**，就进入多轮问答（§4.2）。这是各种 SSH 双因素认证（TOTP、推送确认、菜单选择）的通用做法。
4. 配置的是私钥或 agent、失败后服务器不提供 keyboard-interactive 但**还接受 password**：与 OpenSSH 一样回退到密码（用已保存的密码，没有就向用户要）。密码之后服务器若要求 keyboard-interactive（partial success），照 §4.2 继续。很多堡垒机只开 password + publickey，本机默认私钥不在授权列表里时就靠这一步。回退后仍失败，按密码失败报错。
5. 否则报错，并区分两种情况：
   - **partial success**（凭据已被接受，但服务器还要另一个因素，且没有提供本客户端支持的方式）：说明"凭据已接受，还需要另一个因素，服务器只提供了某某方法"，**不要说密码错误**。
   - 普通失败：说明是哪个用户、用哪种方式失败的；agent 方式要说明"agent 里没有身份被接受"。

### 4.2 keyboard-interactive（RFC 4256）
- 按轮次循环，直到服务器回复成功或失败。**最多 16 轮**，超过就报错，防止服务器一直追问，把连接和用户拖住。
- 某一轮**没有问题、只有文字**（例如"推送已发送"）时，直接空答，并把文字带到下一轮有问题的对话框里一起显示，保证用户能看到。
- **保存的密码只用来回答一种问题**：这一轮恰好只有一个问题、不回显输入、问题文本里含 "password"（不区分大小写），并且认证方式本来就是密码。保存的密码最多自动填一次。**验证码、推送确认、菜单选择绝不能自动用账户密码作答。**
- 其他情况弹出对话框，内容包括：
  - 正在发问的 `host:port`。跳板机会单独发问，要让用户知道是哪一跳在要验证码。
  - 用户名。
  - 服务器提供的标题和说明（通常是空的，空的就不显示）。
  - 每个问题，并按"是否回显"决定输入框是明文还是密码框。
- 用户取消时，终止这次连接，报"认证已取消"。
- 单轮最多等 **180 秒**，超时按取消处理。理由是窗口可能已经关闭，不能让半开的连接一直挂着。
- 服务器最终拒绝时，报"服务器拒绝了验证响应"。

### 4.3 ssh-agent
- Unix 系统：读取 `SSH_AUTH_SOCK`。
- Windows：先用 `SSH_AUTH_SOCK` 指定的命名管道，没有就用 OpenSSH 默认的 `\\.\pipe\openssh-ssh-agent`；都失败再尝试 Pageant。报错时把两种方式各自的失败原因都列出来。
- **[MAS]**：沙盒内无法访问外部 agent 的 socket，因此：
  - 认证方式里不显示 agent 选项。
  - 提供**内置密钥库**作为替代：密钥存在 Keychain 里，可以在 Secure Enclave 中生成不可导出的密钥（ecdsa-sha2-nistp256），使用时可以要求 Touch ID 确认。内置密钥库在所有发行版中都提供，属于 Pro 功能。

### 4.4 凭据存储
- 密码和口令**不明文保存**。mac 存 Keychain；Windows 存 Credential Manager；Linux 存 Secret Service，不可用时退回到加密文件。具体方案在存储规格里定。
- **[MAS]** 私钥文件有两种用法：导入 Keychain，或者通过打开面板授权文件后保存 security-scoped bookmark，之后每次连接时恢复访问权限。

## 5. 跳板机（ProxyJump）

- 跳板机通过引用另一个已保存的会话来指定，而被引用的会话本身也可以有跳板机，于是形成一条链。
- 链最长 **8 跳**。出现循环、引用的会话已被删除、引用的会话不是 SSH 类型，都报错，并说明是哪种原因。
- 保存会话时如果发现跳板引用失效（目标已删除，或者本会话已改成非 SSH 类型），自动清掉这个引用。
- 建立方式：
  - 第一跳直接 TCP 连接。
  - 之后每一跳，都在上一跳上打开一个 `direct-tcpip` 通道（等价于 `ssh -W host:port`），新连接的握手在这个通道里进行。
  - 目标主机在最后一跳上建立。
- **每一跳都使用它自己保存的认证配置和主机密钥策略**。握手是端到端的，跳板机只转发密文，不需要在跳板机上存放目标机的密钥或密码。
- 某一跳打不开到下一跳的通道时，报"跳板机 X 无法到达 host:port"，并附上原因。
- 断开时**从最内层开始，逐层向外**关闭。
- **ProxyCommand**：Direct 版支持（cloudflared、AWS SSM 等场景需要），用外部命令的标准输入输出作为传输通道，`%h %p %r` 按 OpenSSH 规则替换；可以和跳板机二选一，不能同时使用。商店版不支持，因为沙盒内无法可靠地启动外部命令。

## 6. 终端通道

- 认证完成后，打开一个 session 通道：
  - 请求 PTY：终端类型 `xterm-256color`，初始尺寸 80×24，之后按界面实际大小发送 window-change。
  - 设置环境变量 `COLORTERM=truecolor` 和 `TERM_PROGRAM=Kanso`。服务器可能会忽略，失败不报错。
  - 用户在配置里**明确填写了 locale** 时，再设置 `LANG`。只有服务器配置了 `AcceptEnv LANG` 才会生效。locale 的写法只允许字母、数字和 `_ - . @`，长度不超过 64，不合规的值不发送。**自动模式下不发送 LANG**，交给服务器自己的设置。
  - 请求 shell。
- 标准输出和标准错误都送进终端。收到退出码时记下来；通道关闭时，会话标记为"已关闭"，并显示退出码。用户主动关闭的会话，不再提示"连接已关闭"。
- **复制标签 / 分屏**：在**同一个已认证的连接**上再开一个新的 shell 通道，不重新握手、不重新认证，因此需要验证码的会话复制时不会再要一次验证码。
- 连接（含整条跳板链）被多个标签共享时，**最后一个使用者关闭后才真正断开**。多个标签同时关闭时，不能出现重复断开，也不能出现谁都不断开的情况。
- 共享的连接已经断开时，复制标签直接报错，不偷偷重连。
- 写入失败（连接已断）时立即结束会话。

## 7. 纯 SFTP 会话

- 握手、认证、跳板与终端会话完全相同，只是不开 shell 通道。
- SFTP 子系统**在第一次文件请求时才打开**，之后一直复用。SSH 终端会话里的文件面板也是这样。
- 没有通道可读，所以每 5 秒检查一次连接是否还在，断了就把会话标记为已关闭。
- 键盘输入、调整尺寸这类终端操作，在纯 SFTP 会话里直接拒绝。

## 8. SFTP 文件操作

- **家目录**：解析 `.` 的规范路径。
- **列目录**：
  - 先把路径规范化，失败就用原路径。
  - 每一项包含：名称、完整路径、是否目录、是否符号链接、大小、修改时间、权限位、属主、属组。
  - 排序规则在文件面板规格里定（目录在前等）。
  - **性能要求**：大目录要流式返回并逐步显示，不要等全部读完再显示。
- **新建目录**、**删除**（文件和空目录分开处理）、**重命名**。
- **新建空文件**：必须使用"已存在则失败"的打开标志，防止名字打错时把已有文件清空。

## 9. 传输

### 9.1 通用要求
- 上传、下载**都不占用终端会话的处理循环**。大文件传输期间，终端输出不能卡住，其他文件请求也不能卡住。
- 内存占用与文件大小无关，按固定大小的块流式传输。
- 进度回报最多 **每 50 ms 一次**，开始时报 0，结束时报最终值。
- **可以取消**：在块与块之间检查取消标记。取消后要清理半成品：下载就删掉本地的残缺文件；上传就关闭远端文件后删除它，因为残缺文件会被误当成完整文件。
- **性能要求（新版明确提出）**：读写要采用**流水线**方式，同时保持多个在途请求（例如 64 个 × 32 KB），配合大窗口，目标是千兆局域网单文件 ≥ 80 MB/s。逐块"发一个请求、等一个回复"的做法在高延迟链路上非常慢，不能采用。

### 9.2 下载目录
- **先只扫描元数据，生成完整计划**，这样进度条能覆盖整棵目录树。然后在本地创建全部目录，校验每个目标文件路径，最后逐个传输文件。
- 跳过 `.` 和 `..`。
- **符号链接**：指向文件的跟随下载；悬空链接和指向目录的链接跳过，后者可能指回上级目录，形成死循环。
- **本地路径安全**：远端文件名不能让写入跑出目标目录。`..`、绝对路径、路径分隔符都要拒绝。
- 总大小溢出时报错。

### 9.3 上传
- 只上传普通文件。
- 上传目录：先扫描本地，生成计划，然后在远端按顺序创建目录：已经存在的目录直接合并；同名路径如果不是目录，就报错，不覆盖。

### 9.4 [MAS]
- 下载目标位置必须是用户通过保存面板选的，或者已经授权过的目录。
- 上传源文件必须来自打开面板或拖入操作。
- 拖到桌面或 Finder 时使用 file promise，等落点确定后再下载。

## 10. 远端工作目录查询

用途：用户按 ⌘J 时，让文件面板跳到 shell 当前所在的目录。只在用户主动请求时查询一次，不持续跟踪。

- **优先使用 OSC 7**：shell 主动上报的目录在任何系统上都可靠，sudo 或嵌套 shell 里也一样。终端规格里会定义如何解析 OSC 7。
- **没有 OSC 7 时，到服务器上查**：
  - 在同一个连接上另开一个 exec 通道，**不碰正在用的 shell 通道**。
  - 把一段 POSIX sh 脚本通过 stdin 交给 `sh` 执行，避免用户的登录 shell（可能是 csh 或 fish）去解析它。
  - 查找思路：sshd 会给同一个连接的所有进程打上相同的 `SSH_CONNECTION` 环境变量。在 `/proc` 里找出带这个值（必须完全相同）、并且**有控制终端**的进程，也就是 shell 通道（exec 通道没有终端）。再读这个终端**前台进程组**的工作目录，这样嵌套 shell 或从 shell 启动的程序也能查对。
  - 只用 busybox 里也有的命令。
  - 结果行加一个专门的前缀，避免登录 shell 的 rc 文件输出的内容被误当成结果。
  - **5 秒超时**。
  - 失败时按原因给出具体提示：没找到这个连接的 shell；服务器没设置 `SSH_CONNECTION`；前台进程属于别的用户（例如 sudo 或 su）；服务器没有 `/proc`（只支持 Linux）。所有失败提示的末尾都加一句"会上报 OSC 7 的 shell 在任何系统上都能查到"。
  - 有的服务器会在 eof/close 之后才发退出码，要以通道关闭作为结束信号。

## 11. 错误信息

- 每条错误都要指明对象：`host:port`；经跳板机时写成"经由 某某"。
- 无法读取私钥文件时，给出路径和原因。
- 所有面向用户的错误信息都要做本地化（中文、英文）。

## 12. 验收用例（实现时转成自动化测试）

- 只支持旧算法的设备能连上，状态栏显示 Legacy SSH，并列出具体算法。
- 同时支持 NIST 曲线和 SHA-1 的设备，选 NIST 曲线。
- group-exchange 给出 2048 位群时能连上。
- 现代服务器不会落到任何旧算法上。
- russh 默认支持的每个算法都仍在列表里，没有被意外删掉。
- 未知主机记录后，再次连接能识别；同算法密钥变化时拒绝连接；新算法的密钥被记录下来；接受变更后，该主机的所有旧记录都被替换；非 22 端口按 `[host]:port` 格式记录。
- 公钥认证后服务器要求验证码，能把登录走完。
- 服务器不要求任何认证时，直接登录成功。
- 公钥被拒时，报"密钥被拒"。
- partial success 时，不提示密码错误。
- 密码轮自动用保存的密码作答；验证码轮不会自动作答。
- 通过跳板机能同时打开 shell 和 SFTP。
- 取消下载后，本地不留下残缺文件。
- 大文件传输期间，内存占用有上限；取消后在下一个块处停止。

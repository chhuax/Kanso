# 多语言

总体设计见 architecture.md §10。本文是日常开发的操作规则。

## 分层

| 来源 | 位置 |
|---|---|
| mac UI 文字 | `Localizable.xcstrings`（String Catalog） |
| core 产生的消息（错误、认证提示、传输状态） | `locales/<lang>.ftl`（Fluent），唯一来源 |

core 只返回 `kanso-types` 的 `Message`（key 加命名参数），由 `kanso-l10n` 渲染成文字（见下文“渲染”）。首发语言：`en`、`zh-Hans`。

## key 与参数命名

- key：`<领域>-<名称>`，全小写 kebab-case，只含 `[a-z0-9-]`，以字母开头。
- 参数名：snake_case，即 Fluent 里的变量名；同名参数在不同消息里类型必须一致。
- 现有领域：`profile`、`ssh`、`hostkey`、`auth`、`jump`、`session`、`cwd`、`sftp`、`xfer`、`zmodem`、`xmodem`、`import`、`sshconfig`、`secret`；子 key 领域：`reason`、`endpoint`。
- `.ftl` 里按领域分段，段首写 `## 领域`。

## 新增一条 core 消息

1. 在 `kanso-types` 的 `messages!` 清单加一行（key、参数）。
2. 在每个 `locales/*.ftl` 里加翻译：使用该消息声明的全部参数，不引用未声明的变量。
3. 运行 `cargo xtask check-locales`，通过后再提交。

`check-locales` 检查：`.ftl` 无语法错误（Junk 会报位置）；key 集合等于 `CATALOG` 加 `AUX_KEYS`（缺少、未使用）；每条消息引用的变量集合等于声明的参数集合；对 Select 参数用了选择表达式时，`ALL_KEYS` 的每个值都要有分支（另需一个 `*` 默认分支，Fluent 语法本身要求）。所有问题一次性列出。

## 渲染

core 消息在 Rust 里用 `fluent-bundle` 运行时渲染：`crates/kanso-l10n` 把 `locales/en.ftl`、`locales/zh-Hans.ftl` 编进二进制，提供 `render(&Message, languages)` 与面向 FFI 的 `render_key`；`kanso-ffi` 导出 `render_message(message, languages)`，Swift 通过 `CoreMessageText.text(_:)` 调用。**不再**把 `.ftl` 生成 String Catalog：Fluent 的 select、复数与 `reason-*` / `endpoint-*` 嵌套无法忠实映射到 String Catalog，由 Rust 渲染才能让 `.ftl` 成为唯一来源，GPUI 版也直接复用同一个渲染器。

- 语言协商：按 `languages` 顺序取第一个受支持的。`zh`、`zh-Hans`、`zh-Hans-CN`、`zh-CN`、`zh_CN` 等归到 `zh-Hans`；`zh-Hant`、`zh-TW`、`zh-HK` 不归简体（跳过，都不支持则回退英文）；`en-*` 归 `en`；都不支持回退 `en`。
- Swift 的默认语言是 `Bundle.main.preferredLocalizations`，已反映“按 App 设置语言”。
- 渲染不会 panic：key 不存在返回 key 本身，缺变量等错误返回尽量完整的文本；debug 构建会 `debug_assert!` 报出，release 只记日志。
- 渲染器关闭了 Fluent 的双向隔离符，否则每个变量两侧会带 U+2068/U+2069。
- 新增语言：加 `locales/<lang>.ftl`、在 `kanso-l10n` 的 `Lang` 与资源表里登记，并更新协商测试。

## 参数类型与平台格式化

| 类型 | 处理方式 |
|---|---|
| `Str` | 原样代入（文件名、路径、主机名等数据） |
| `Int` | 作为数字传给 Fluent，可用 `[one]` / `*[other]` 做复数选择（英文计数类消息要这样写） |
| `ByteSize` | Swift 先用系统格式化器（`.file` 风格）转成 `1.2 MB` 之类的字符串，作为 `Str` 传给渲染器；Rust 侧只有兜底格式 |
| `StrList` | Swift 先用 `ListFormatter` 连接成一个字符串，作为 `Str` 传给渲染器；Rust 侧兜底用 `, ` 连接 |
| `Select` | 取值是 `SelectKey::ALL_KEYS` 之一的字符串，消息里用选择表达式写出每个取值再加 `*` 默认分支 |
| `Reason` | 渲染器先用 `reason-*` 子 key 渲染成字符串再代入；`reason-other` 使用 `$detail`（英文技术细节，不本地化） |
| `Endpoint` | 渲染器先用 `endpoint-direct`（`$host_port`）或 `endpoint-via`（`$host_port` 与 `$via`）渲染成字符串再代入；`host_port` 由 `Endpoint::host_port()` 提供 |

所以主消息里 Reason / Endpoint 参数当作普通字符串变量引用（`$reason`、`$endpoint`）。日期、相对时间同样用平台格式化器；时间戳栏固定 `HH:MM:SS.mmm`，不随语言变化。

## 特殊文案规则

- `cwd-*` 全部以“会上报 OSC 7 的 shell 在任何系统上都能查到”的意思结尾（ssh.md §10）。
- `auth-partial-success` 不得出现“密码错误”之类的说法（ssh.md §4.1）：凭据已被接受，只是还缺另一个因素。
- 中文用简体、语气平实；英文用简洁的 sentence case。

## 禁止事项

- 不要在 Rust 里用 `format!` 拼用户可见的句子。需要新文案就新增 `Message`。日志例外，日志一律英文。
- 不要在 `.ftl` 之外另存 core 消息的翻译（包括 String Catalog）。
- 终端内容不做本地化。
